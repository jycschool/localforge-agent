# 用例文档

## 1. 参与者

- **开发者**：提交任务、提供上下文、审批命令、审查变更并决定是否继续。
- **模型服务**：根据消息和工具定义返回文本或原生工具调用。
- **本地工作区**：提供代码、配置和测试环境。
- **LocalForge**：组织上下文、执行 agent 循环、调用本地工具并呈现结果。

## UC-01 完成一个局部功能开发

**前置条件**：VS Code 已打开一个工作区；API key 和模型配置有效。

**触发**：开发者输入“为配置模块增加环境变量覆盖，并补充测试”。

**主流程**：

1. LocalForge 收集工作区、活动文件和选区信息。
2. 模型调用文件搜索与读取工具定位实现和测试。
3. 模型调用修改工具更新代码和测试。
4. 模型请求执行测试，开发者批准命令。
5. 测试失败时，错误输出返回模型，模型继续定位和修复。
6. 测试通过后，模型返回完成说明。
7. LocalForge 展示摘要、验证结果、变更文件和 Diff 入口。

**后置条件**：修改保留在本地工作区，未自动提交或推送。

**异常流程**：

- A1：文件不存在或内容已变化，工具返回结构化错误，模型重新读取后再修改。
- A2：用户拒绝命令，拒绝原因作为工具结果返回模型，模型选择替代验证或结束。
- A3：达到最大步骤，系统停止并保留已有变更，提示用户继续新一轮任务。
- A4：用户点击停止，当前模型请求或本地进程被取消。

## UC-02 解释当前代码

1. 开发者选中一段代码并询问其行为。
2. LocalForge 自动附加选区及文件路径。
3. 模型可继续读取相关定义，但不必修改文件。
4. 系统给出解释，并在时间线中标明只读工具调用。

验收重点：不要求用户重复粘贴当前代码；只读任务不会产生变更记录。

## UC-03 修复失败测试

1. 开发者提供失败测试名称或错误现象。
2. 智能体搜索测试与实现，运行最小相关测试。
3. 智能体根据输出修改代码并重新运行测试。
4. 最终摘要区分“目标测试通过”和“完整测试套件未运行”。

验收重点：不会把局部通过表述为全部通过；失败输出进入下一轮决策。

## UC-04 审查和继续修改

1. 任务完成后，开发者打开某个变更文件的 Diff。
2. 开发者在同一侧边栏要求调整实现。
3. 新要求与已有对话和变更摘要共同进入下一轮。
4. LocalForge 更新 Diff 和验证结果。

## UC-05 命令审批

1. 智能体提出命令并说明用途。
2. UI 展示命令、工作目录和风险提示。
3. 开发者选择“仅本次允许”或“拒绝”。
4. LocalForge 执行或返回拒绝结果，不伪造执行成功。

## UC-06 配置模型

1. 开发者在设置中填写 API Base URL 和模型名。
2. 开发者通过命令面板录入 API key。
3. API key 写入 VS Code SecretStorage。
4. 后续请求读取密钥但不会显示其明文。

## 2. 演示用例

演示项目选择一个已有测试的小型 TypeScript 项目。任务应同时涉及源文件和测试文件，并预设一个可通过真实测试暴露的问题，以展示“首次修改 - 测试失败 - 读取错误 - 二次修复 - 测试通过”的闭环。
