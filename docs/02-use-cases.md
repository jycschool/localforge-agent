# 用例文档

## 1. 参与者

- **开发者**：打开项目、查看代码、提交任务、审批命令和审查变更。
- **模型服务**：根据消息与工具定义返回文本或原生工具调用。
- **本地项目**：提供源代码、配置和测试环境。
- **LocalForge**：编排 Agent 循环、执行受限工具并呈现过程与结果。

## UC-01 打开项目并理解结构

**前置条件**：LocalForge 已启动。

1. 开发者点击“打开项目”并选择本地目录。
2. LocalForge 解析真实根路径，过滤依赖、构建、缓存与版本控制目录。
3. 左侧显示项目目录树；用户展开目录并点击文件。
4. 中间显示文件语言、大小和只读内容。

**验收重点**：不依赖外部编辑器；大于 1 MB 的文件不进入预览；项目外路径和逃逸符号链接被拒绝。

## UC-02 完成一个局部功能开发

**前置条件**：项目已打开；模型配置与 API Key 有效。

**触发**：开发者输入“为配置模块增加环境变量覆盖，并补充测试”。

1. LocalForge 将任务和当前选中文件路径交给 AgentLoop。
2. 模型调用列表、搜索和读取工具定位实现与测试。
3. 模型使用精确替换或写入工具修改文件；ChangeTracker 保存首个原始版本。
4. 模型提出测试命令和原因，桌面审批框显示命令与工作目录。
5. 开发者批准；命令输出、退出状态和耗时返回模型并显示在界面。
6. 若测试失败，模型读取错误、继续修改并再次申请验证。
7. 完成后 LocalForge 展示摘要、变更文件和双栏 Diff。

**后置条件**：修改留在本地项目中，不自动提交或推送。

**异常流程**：

- A1：旧文本不存在或出现多次，工具拒绝含糊修改，模型重新读取。
- A2：开发者拒绝命令，拒绝结果返回模型，模型选择替代验证或结束。
- A3：达到最大步骤，系统停止并保留时间线与已有改动。
- A4：开发者点击停止，模型请求或本地进程被取消。

## UC-03 解释某个文件

1. 开发者从目录树选择文件并输入解释请求。
2. LocalForge 把选中文件路径作为任务上下文。
3. 模型通过只读工具获取必要代码及相关定义。
4. 系统展示解释与只读工具过程，不生成变更记录。

## UC-04 修复失败测试

1. 开发者描述失败测试或错误现象。
2. Agent 搜索测试与实现，申请运行最小相关命令。
3. Agent 根据真实 stderr/stdout 修改代码并重新验证。
4. 最终摘要区分“目标测试通过”和“完整测试套件未运行”。

## UC-05 审查并继续修改

1. 任务完成后，开发者在“本次变更”中选择文件。
2. 中间区域并排显示任务前快照和当前内容。
3. 开发者继续提交调整要求；新任务针对当前工作区执行。

## UC-06 命令审批

1. Agent 调用 `run_command` 并提供用途说明。
2. 模态框显示原因、完整命令和固定 cwd。
3. 开发者选择“允许执行”或“拒绝”。
4. LocalForge 只执行已批准的调用，并把真实结果返回 Agent。

## UC-07 配置模型

1. 开发者打开设置，填写兼容 API 地址、模型名、Key、最大步骤与超时。
2. 主进程验证配置；Key 使用 Electron `safeStorage` 加密后保存。
3. Renderer 只知道“是否已有 Key”和来源，不读取明文。
4. 若存在 `LOCALFORGE_API_KEY`，环境变量优先且不落盘。

## 2. 演示用例

演示使用带测试的小型 TypeScript 项目，任务同时涉及源文件和测试文件，并预设一个会由真实测试暴露的问题。视频展示“打开项目—查看结构—提交任务—批准测试—首次失败—二次修复—测试通过—审查 Diff”的闭环。
