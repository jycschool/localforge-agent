# 开发日志

## 2026-08-27：项目基线、自研闭环与桌面形态

### 第一阶段：基线与 Agent 核心

- 阅读并拆解考核约束、交付物和面试关注点。
- 建立需求、用例、设计、原型、计划、测试、风险和追踪文档。
- 初始化 Git 与 GitHub 公开仓库 `jycschool/localforge-agent`，保留真实提交历史。
- 完成 OpenAI-compatible 模型客户端和原生 tool calling 消息协议。
- 完成 AgentLoop、ToolRegistry、最大步骤、取消和错误回传。
- 完成受工作区约束的列表、搜索、读取、精确替换、写入和命令工具。
- 完成命令逐次审批、超时、输出上限和 ChangeTracker。

### 第二阶段：从 VS Code 扩展调整为独立桌面应用

- 评审发现：即使 Agent 核心自研，借助 VS Code 的文件树与 Diff 仍可能让评审者难以判断实现边界。
- 保留全部 Agent 核心，删除 Extension Host、Webview 和 VS Code API 依赖。
- 新增 Electron 主进程、沙箱 Preload、独立 Renderer 和 IPC contracts。
- 新增打开项目、过滤目录树、只读代码预览、双栏 Diff、运行输出、时间线和停止操作。
- 新增主进程命令审批、项目切换互斥与任务单实例控制。
- 新增 safeStorage 配置存储；Renderer 只能看到 Key 是否存在。
- 将 Python 虚拟环境、依赖、缓存和构建目录排除在项目树与 Agent 默认遍历之外。
- 更新 ADR：0001 保留为历史并由 0002 正式取代。

### 验证证据

- `pnpm run check` 通过。
- `pnpm test` 通过：8 个测试文件、25 项测试，覆盖 Agent 生命周期、路径边界、工作区工具、命令拒绝、桌面项目服务以及 Skill/Memory 上下文。
- `pnpm run build` 通过，生成 Electron main、preload 和 renderer 构建。
- 桌面窗口真实启动成功；三栏布局、打开项目、目录树和系统辅助功能结构完成首轮检查。
- 在含 Python 虚拟环境的大项目上发现文件树噪音并完成修正。

### 第三阶段：Skill、Memory 与前端优化

- 从项目 `.localforge/skills/*.md` 发现 Markdown Skill；任务只注入用户勾选且运行时仍存在的内容。
- 新增按项目真实路径隔离的 Memory，保存在 Electron 应用数据中，并设置 12,000 字符上限。
- 系统提示明确 Memory 可能过期，事实必须用当前文件核实；Skill 不得覆盖路径、审批和安全边界。
- 右侧输入区新增紧凑的 Skill/Memory 状态按钮和独立弹窗，没有继续挤压时间线。
- 项目目录改为按展开状态构建 DOM；时间线和运行输出设置上限，降低大项目与长任务的前端负担。

### 计划偏差与判断

桌面形态调整增加了 UI 和 IPC 工作，但核心模块无须重写，首日仍完成了可构建、可启动版本。独立产品形态更有利于答辩：可以明确指出 Electron 是展示层，而 AgentLoop、工具协议、本地执行与安全边界全部来自本仓库。真实模型端到端验证仍是下一阶段最大不确定项，不能用单元测试代替。
