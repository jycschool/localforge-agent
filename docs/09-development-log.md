### 第二阶段：从 VS Code 扩展调整为独立桌面应用

- 评审发现：即使 Agent 核心自研，借助 VS Code 的文件树与 Diff 仍可能让评审者难以判断实现边界。
- 保留全部 Agent 核心，删除 Extension Host、Webview 和 VS Code API 依赖。
- 新增 Electron 主进程、沙箱 Preload、独立 Renderer 和 IPC contracts。
- 新增打开项目、过滤目录树、只读代码预览、双栏 Diff、运行输出、时间线和停止操作。
- 新增主进程命令审批、项目切换互斥与任务单实例控制。
- 新增 safeStorage 配置存储；Renderer 只能看到 Key 是否存在。
- 将 Python 虚拟环境、依赖、缓存和构建目录排除在项目树与 Agent 默认遍历之外。
- 更新 ADR：0001 保留为历史并由 0002 正式取代。

### 第三阶段：Skill、Memory 与前端优化

- 从项目 `.localforge/skills/*.md` 发现 Markdown Skill；任务只注入用户勾选且运行时仍存在的内容。

- 完成第二轮视觉重构：统一低饱和蓝紫强调色，弱化硬分割线，增加目录行高、欢迎页层级、时间线空状态、浮动任务卡和柔化弹窗。

### 第四阶段：任务历史与模型协议加固

- 新增 `RunHistoryStore`，使用项目真实路径摘要隔离本机历史；记录任务状态、摘要、步骤、事件、消息和改动文件。
- 任务开始时先落盘，正常完成、失败或停止后原子更新；应用重启后遗留的运行中记录显示为“意外中断”。
- 历史设置每项目 50 次、每次 200 条事件和 160 条消息上限；不保存 API Key，并移除 assistant reasoning 内容。
- Agent 标题栏新增紧凑历史入口；弹窗使用列表/详情布局展示状态、结果、过程和改动文件，不增加主工作区列数。
- 强化 OpenAI-compatible 响应解析：严格校验顶层对象、choices、文本分段、tool call 类型、ID、工具名和参数对象。
- 损坏调用与重复 call id 不再被静默过滤，从而避免把协议错误误判为任务完成。
- 在真实 Electron 窗口打开当前项目并检查历史空状态，确认布局、文案和辅助功能结构正常。

### 第五阶段：Windows 命令执行稳定性

- 命令输出改用流式 UTF-8 解码，避免中文字符落在数据块边界时出现替换字符。
- Windows 超时或取消时调用系统进程树终止，不只关闭外层 shell；POSIX 使用独立进程组并提供强制终止兜底。
- 输出截断改为记录真实截断标志，恰好达到上限时不再误报。
- 新增成功、非零退出、超时、取消、子进程清理、中文 stdout/stderr 和输出截断测试；超时测试会等待确认后代进程没有写出存活标记。
- 时间线和运行输出新增退出码、用户拒绝、超时终止及“仅保留末尾”的明确提示。
