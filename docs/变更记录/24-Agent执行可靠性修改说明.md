# Agent 执行可靠性修改说明

## 1. 变更目的

真实模型测试表明，工具调用效果不佳不应只靠延长提示词或提高步骤上限解决。弱模型可能反复读取相同文件、在两个搜索之间循环、用过期内容编辑，或修改后未验证就输出最终答复。本次变更将这些问题分别落实为工具协议、Agent 状态和完成门禁，而不是要求模型“更认真”。

## 2. 提示词边界

系统提示词只增加三条可执行规则：编辑已有文件前读取最新相关内容；列表或搜索被截断时缩小范围后再下结论；工具失败后区分路径、参数、过期内容、权限和命令结果并更换策略。身份、安全、计划和最终回答规则不重复扩写，避免提示词膨胀和相互冲突。

## 3. 结构化工具错误

`ToolExecutionError` 和 `toolErrorResult` 统一提供 `error`、`code`、`retryable`、`suggestion` 与可选 `details`，同时保留原字符串 `error` 以兼容现有界面、历史和报告。未知工具、阶段禁用、非法参数、文件不存在、越界路径、过大文件、替换未命中/不唯一、命令拒绝、失败和超时均能给模型明确的恢复方向。

## 4. 安全按行编辑

`read_file` 增加总行数和完整文件 SHA-256。新工具 `edit_file_lines` 要求项目相对路径、1 起始行范围、最近读取摘要和替换文本；写入前重新读取并比较摘要，文件变化时返回 `STALE_FILE_CONTENT`。工具保留原换行风格、限制最终文件大小、接入 ChangeTracker，并返回前后摘要。该工具位于精确字符串替换和完整覆盖之间，降低弱模型因空格或换行差异导致的失败，同时不牺牲并发安全。

## 5. 循环与步骤预算

原有“三次完全相同失败”熔断继续保留。新增最近八次动作窗口，对相同读取/搜索结果和同工具同错误码进行循环识别；第一次发现时向模型注入纠偏要求，只有在没有成功写入、命令或计划推进的情况下再次形成循环才停止。成功副作用会清空循环警告，避免把后续独立问题误判为同一循环。达到硬上限前三轮时增加收尾提示，但不静默突破用户配置。

## 6. 直接模式完成门禁

`DirectCompletionPolicy` 配对 `tool_started` 与 `tool_finished`：成功写入后把文件标记为待验证，重新读取该文件或成功运行命令后清除。模型第一次在仍有待验证文件时输出最终答复会被阻止；验证失败时要求修复或明确风险。为避免用户拒绝命令后只能耗尽步骤，同一修改版本只阻止一次，下一次答复可以诚实报告未验证事项。计划模式仍由 `PlanController` 和 `finish_task` 负责，二者不混用。

## 7. 验证范围

- 提示词包含三条新增操作规则。
- 工具注册中心保留结构化错误信息。
- 按行编辑成功、过期摘要、换行和 ChangeTracker 行为。
- 直接模式修改后阻止一次、读取后放行、成功命令清空和失败说明。
- A/B 交替读取循环先纠偏再停止。
- 剩余三轮时提示模型收尾。
- 主进程仍只在计划模式允许工具后直接完成；直接模式必须等待模型看到工具结果并提交最终答复。

本次没有引入第二个模型、隐藏思考链、自动扩大步骤上限或自动批准命令，也没有改变工作区路径和人工审批边界。
