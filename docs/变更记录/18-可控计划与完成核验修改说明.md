# 可控计划与完成核验修改说明

## 1. 变更原因

原版本已经具备“模型输出工具调用—本地执行—结果回传—模型继续决策”的 ReAct 型循环，但复杂任务会直接进入修改：用户只能逐次审批命令，不能在副作用发生前确认整体范围；模型输出最终文本时也缺少一个独立于模型自述的完成门禁。为提升可控性和答辩中的可解释性，本版本增加任务级计划模式，同时保留原有直接执行模式，避免简单问答被强制增加审批。

## 2. 范围与用户交互

- 输入区新增“直接执行/先规划”。直接执行保持原流程；先规划用于多文件修改、架构调整或风险较高的任务。
- 计划模式允许 Agent 先用只读工具调查，再提交 1—12 个可验证步骤。
- 内嵌确认卡允许用户改写、上下移动、添加和删除步骤；批准前不开放文件写入或命令。
- 批准后显示实时清单。执行中若目标、文件范围、架构或风险发生实质变化，必须提交新修订并再次确认。
- 所有步骤完成或跳过后，Agent 必须记录至少一项实际核验证据；未完成事项单独列出。最终计划进入历史详情和 Markdown 证据报告。

## 3. 核心设计

### 3.1 不是只靠提示词

System prompt 用结构化章节说明角色、指令层级、不可信内容、工具纪律、验证和当前执行策略；工具 schema 也补充了路径语义、覆盖风险、参数边界与核验要求。但权限控制不依赖模型服从：`PlanController` 根据状态动态过滤 ToolRegistry 的 schema，并在执行入口再次检查工具是否可用。

未获批时只允许 `list_files`、`search_text`、`read_file` 和 `propose_plan`。获批后才恢复当前权限模式本来允许的工具；若用户选了只读权限，批准计划后仍没有修改与命令工具。

### 3.2 ReAct 与 Reflection 的处理

LocalForge（现 RepoForge）不保存或展示模型私有思考链。可观察循环由 assistant 工具调用、工具结果和下一轮决策组成，这已经提供了 ReAct 的 Action/Observation 证据。Reflection 不额外要求一段不可验证的“自我反思”文字，而通过两层确定性检查实现：

1. `update_plan` 要求提交完整清单，且同时最多一项为进行中；步骤只有在实际检查后才应标记完成。
2. `finish_task` 要求所有步骤进入完成或跳过状态，并记录实际核验与遗留事项。模型若在门禁通过前输出最终文本，AgentLoop 发出 `completion_blocked`，向下一轮加入明确纠正信息并继续运行。

这种方案不会把“模型说已经反思过”误当作质量证据，用户可以从清单、命令退出码、Diff、核验记录和历史事件交叉检查。

### 3.3 数据与 IPC

- `RunRequest.executionMode` 默认为 `direct`，兼容旧 Renderer 和旧历史。
- 计划确认使用独立请求/事件 IPC。Renderer 只回传批准标志和编辑后的步骤；主进程重新校验类型、数量、非空标题和长度。
- `PlanSnapshot` 保存修订号、状态、步骤、核验和遗留事项；最终快照随任务详情持久化，历史索引只记录执行模式，避免索引膨胀。
- 任务停止、窗口关闭或运行收尾会同时解除命令审批和计划审批等待，不留下悬挂 Promise。

## 4. 状态与终止规则

| 状态 | 可用能力 | 离开条件 |
| --- | --- | --- |
| 未规划/退回 | 只读工具、提交计划 | 提交新计划并获批 |
| 等待确认 | 不进入下一工具执行 | 用户批准或退回 |
| 执行中 | 当前权限允许的项目工具、更新/修订计划 | 全部步骤终态或提交修订 |
| 等待完成核验 | 完成工具、必要的复核工具 | `finish_task` 接受核验证据 |
| 已完成 | 不再暴露工具 | 下一条非空最终文本产生 `completed` |

最大步骤、用户停止、协议错误、重复失败熔断和命令逐次审批继续生效。规划模式不会绕过这些既有终止条件。

## 5. 安全与兼容边界

- 项目文件、附件、工具输出、Memory 和 Skill 统一标为潜在过期或恶意数据，不能覆盖系统边界或用户本轮要求。
- 计划确认不是权限提升，也不是命令批准；计划内的每条本地命令仍需单独确认。
- 直接执行是默认值，旧任务历史读取时也归一化为直接执行。
- 历史接续只使用用户和 Agent 可见文本，不重放旧计划工具、命令调用或工具结果。
- 不新增 Agent SDK、工作流框架或前端框架；状态机、工具门禁、IPC 和界面均在现有 TypeScript/Electron 架构内自行实现。

## 6. 验收与回滚

自动化覆盖计划前副作用隔离、编辑后批准、修订退回、清单约束、完成门禁、历史/报告和 IPC 入参。候选版还应人工完成一次“选择先规划—编辑顺序—确认—批准命令—观察步骤—查看历史报告”的真实模型闭环。

若真实兼容模型无法稳定调用计划工具，可把任务切回直接执行，不影响既有 AgentLoop、WorkspaceTools、历史、Diff 和命令审批；若发现阻塞缺陷，也可暂时隐藏计划选项并停用三个计划工具，不需要迁移项目数据。
