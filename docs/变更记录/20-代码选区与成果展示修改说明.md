# 代码选区与成果展示修改说明

## 1. 变更背景

截至 2026 年 8 月 29 日，RepoForge 已能完成计划、读改测、审批、Diff 和历史闭环，但用户从“正在看的代码”发起任务仍需手工描述路径与范围，任务结束后的证据也分散在回复、时间线、输出和变更区。为提升实际操作效率与演示辨识度，本次经确认新增三项相互衔接的 P1 能力：代码选区快捷任务、任务成果卡和历史过程回放。

## 2. 需求范围

### 2.1 代码选区快捷任务

- FILE 预览和轻量编辑区支持非空文本选区；DIFF 保持只读审查，不提供快捷任务。
- 浮动条显示选区行号，并提供解释、查错、修改、生成测试和加入任务五种模板。
- 文件相对路径、起止行号和最多 8,000 字符正文写入右侧普通任务框；已有草稿只追加、不覆盖。
- 生成草稿不调用模型，用户仍可编辑、选择执行模式并明确发送。

### 2.2 任务成果卡

- 完成卡展示变更文件与增删行、工具调用与失败、命令/可识别测试数和 Token。
- 数据来源限定为本次 `AgentEvent`、成功命令输出和 `ChangedFileSnapshot`，不接受模型总结中的自报数字。
- 指标随任务历史保存，并进入历史详情与 Markdown 证据报告；旧记录没有字段时明确降级。

### 2.3 历史过程回放

- 历史详情按原顺序依次点亮已持久化事件，显示当前项/总数并在约数秒内完成。
- 用户可停止或重新回放；切换记录和关闭弹窗会清理计时器并恢复全部记录。
- 回放只修改 Renderer 展示状态，不通过 Preload，不请求模型、不执行工具、不修改项目或历史，也不消耗 Token。

## 3. 数据流与安全边界

```text
代码选区 → Renderer 计算偏移/行号 → 生成可编辑任务草稿 → 用户明确发送 → 既有 AgentLoop

AgentEvent + ChangeTracker 快照 → RunOutcome 可信计算 → 实时成果卡
                                              └→ RunHistoryStore → 历史成果卡/报告/本地回放
```

- 选区任务复用现有 `RunRequest.task`，没有新增通用 IPC 或文件权限。
- 任务字段仍由 Renderer 20,000 字符限制与主进程校验双重保护；Skill、Memory、附件、计划门禁和命令审批不因选区入口改变。
- 行数对小文件使用行级最长公共子序列计算；规模过大时退化为边界统计并标记“约”，避免为视觉统计阻塞界面。
- 测试数只识别成功命令输出中的常见确定格式，未识别时显示命令次数，不把模型文本当作测试证据。

## 4. 明确不做

- 不加入语言服务器、AST 重构、右键 IDE 菜单或代码补全。
- 不在选中代码后自动发送请求，也不自动切换权限或执行模式。
- 不把回放包装成真实时间旅行，不恢复当时文件状态，不重放网络与命令。
- 不为了增删行统计引入重型 Diff/编辑器依赖。

## 5. 验收标准

- 选中 `src/shipping.mjs` 第 12—15 行后，浮动条行号正确；“生成测试”形成包含路径、行号和代码围栏的可编辑草稿，模型请求数保持不变。
- 成果纯函数能从受控事件识别工具、命令、失败、测试和 Token，并对一个替换加新增的文件给出正确增删行。
- 新任务历史保存结构化成果字段，导出报告包含同一指标且不含 reasoning 或 Key。
- 回放节奏有界，停止、完成和关闭时无残留计时器，代码路径不调用 Desktop API。
- `pnpm run verify`、`pnpm run verify:delivery` 和最新 Windows 候选构建桌面检查通过。
