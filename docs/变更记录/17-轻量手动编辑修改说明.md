# 轻量手动编辑修改说明

## 1. 修改原因

LocalForge（现 RepoForge）原本只能预览项目文件，并由 Agent 工具完成所有写入。该边界有利于证明 Agent 闭环，却使用户无法修正一个小拼写、补充说明文件或在演示前快速准备输入。经评审，本版本增加轻量手动编辑，同时继续保持“独立 Agent 工作台而非完整 IDE”的产品定位。

## 2. 批准范围

- 编辑当前已打开的 UTF-8 文本文件。
- 用保存按钮或 `Ctrl+S` 写盘；取消不会产生文件变化。
- 在已经存在的项目内目录中新建一个文本文件。
- 保存前检测外部变化，冲突时保留磁盘内容。
- 明确区分用户手动修改与 Agent 修改。

## 3. 明确不做

- 不加入 Monaco、CodeMirror、语言服务器、自动完成、诊断或格式化。
- 不增加文件夹创建、重命名、移动、删除和二进制编辑。
- 不实现多标签页、搜索替换、终端、调试器或 Git UI。
- 不允许编辑器绕过项目根目录、文件大小和任务运行锁。

## 4. 交互变化

项目结构标题新增“新建文件”。FILE 预览标题新增“编辑”；进入后显示“保存”和“取消”，路径、复制和 FILE/DIFF 语义不变。编辑区存在未保存内容时，切换文件、刷新项目、打开其他项目、快速打开或发送 Agent 任务都会被阻止。首次点击取消提示确认，第二次才放弃。

新建弹窗只接收项目内相对路径和初始正文。父目录不存在或目标重名时保留输入并显示错误；成功后关闭弹窗、刷新项目树并打开新文件。

## 5. 数据契约与流程

读取结果新增 `contentHash`。保存请求包含 `relativePath`、`content`、`expectedHash`；新建请求包含 `relativePath` 和 `content`。Renderer 不能指定绝对路径，也不能声明保存成功。

主进程依次执行空闲状态、入参类型、项目授权、词法路径、真实路径、文本与 1 MB 限制、内容摘要检查。保存成功后返回新的文件快照和 Agent 变更列表；新建使用排他写入，不能覆盖目标。

## 6. 变更归因

Agent 写入继续由 `ChangeTracker` 捕获首次快照并生成 Diff。手动新建不进入该跟踪器；手动保存一个已被 Agent 跟踪的文件时，从本次 Agent 变更区移除该路径。这样不会把用户后续内容归到模型名下，也不会提供一个已失真的“一键恢复 Agent 修改”。Git 工作区仍保留真实文件变化。

## 7. 安全与一致性

- 既有文件经过词法与 `realpath` 双重项目边界检查。
- 新文件的已存在父目录经过真实路径检查，目标使用排他创建。
- 正文按 UTF-8 字节计算，最多 1 MB，并拒绝 NUL。
- 当前磁盘摘要与打开时摘要不同即拒绝保存。
- Agent 运行时前后端同时拒绝手动写入。
- Renderer 仍没有 Node 文件系统权限，只使用两个固定 IPC。

## 8. 验收清单

1. 打开文本文件，编辑后 `Ctrl+S` 成功，重读内容一致。
2. 未修改时可退出；有修改时取消需要二次确认且不写盘。
3. 新建嵌套在已存在目录中的文本文件成功并自动打开。
4. 重名、父目录不存在、路径越界、符号链接逃逸、NUL 和超过 1 MB 均失败且不写盘。
5. 外部修改后保存产生冲突，不覆盖外部内容。
6. Agent 运行时保存与新建不可用。
7. 手动保存 Agent 已改文件后，该路径退出本次 Agent 变更区。
8. Preload 只暴露固定方法，主进程拒绝畸形请求。

## 9. 风险与回退

主要风险是混合修改难以逐段归因、编辑中误切换上下文和外部程序并发写入。本方案分别采用解除 Agent 跟踪、未保存导航锁和摘要冲突检查。若候选版本出现阻塞问题，可隐藏编辑/新建入口并移除两个 IPC，原预览、Agent 工具和 Diff 流程不受数据迁移影响。
