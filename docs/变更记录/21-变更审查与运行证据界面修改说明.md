# 变更审查与运行证据界面修改说明

## 1. 变更背景

原“本次变更”只有文件路径，“运行输出”则将多次命令拼接为一段终端文字。两者具备基本功能，但用户需要逐项打开或阅读长输出才能判断改动规模与验证进度，也不利于在短视频中快速证明真实读改测闭环。本次不增加新的副作用能力，只把已有本地证据组织成更清晰的界面。

## 2. 本次变更

### 2.1 结构化变更列表

- 每个文件显示新增或修改状态、文件类型图标、项目内路径及可信增删行。
- 用低饱和比例条表达新增/删除构成；标题显示总体 `+/-` 和“已审查 x/y”。
- 打开某个 Diff 后只在当前 Renderer 会话标记为已审查；不写项目、不进入模型上下文，也不冒充代码评审结论。
- 行数复用成果卡的本地快照计算；大文件退化统计继续带“约”标记。

### 2.2 结构化命令卡

- `run_command` 开始时立即出现执行中卡片，结束后更新成功、失败、拒绝、超时、退出码、执行耗时、批准等待和截断信息。
- stdout 与 stderr 分区显示；成功卡默认折叠，失败和拒绝卡默认展开。
- 输出支持全部、错误、测试筛选以及可暂停的自动跟随；最多保留最近 30 条命令卡。

### 2.3 测试进展

- 从 Node TAP、Vitest 等明确格式中识别通过、失败和总数。
- 同一任务多次执行测试时显示“首次 → 最终”进展及紧凑比例条。
- 只解析工具返回的真实命令输出；格式未知时不展示数量，不从模型总结猜测。

## 3. 数据流与边界

```text
ChangedFileSnapshot → 纯函数行数计算 → A/M、+/-、审查进度 → 打开既有 Diff

run_command started → 执行中卡片
run_command result  → 解析退出码/stdout/stderr/耗时 → 命令卡
                                      └→ 确定格式测试结果 → 首次/最终进度
```

- 没有新增 IPC、工具、文件权限、模型请求或持久化格式。
- 命令仍必须逐次审批；卡片只是既有结果的 Renderer 展示。
- 不实现终端模拟器、实时 ANSI 仿真、测试框架插件或模型生成的影响分析。
- 模型文本和隐藏 reasoning 不作为变更行数、退出状态或测试进度来源。

## 4. 验收结果

- 新增纯逻辑测试覆盖新增/修改行数、TAP/Vitest、命令拒绝、退出码、耗时和进度比例。
- 当前共 29 个测试文件、135 项测试通过，类型检查和构建通过。
- 最新 Windows 构建已打开，空状态、筛选工具条、三列布局与可调上下分区显示正常。
