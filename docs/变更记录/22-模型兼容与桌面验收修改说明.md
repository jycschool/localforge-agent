# 模型兼容与桌面验收修改说明

## 1. 变更背景

2026-08-30 的 ModelScope 真实任务同时暴露了兼容服务差异和一个步骤终止边界：坏工具参数与元数据流分片会中断循环，复杂计划参数不够稳定，模型在最后一步完成核验后仍可能被判定为达到上限。文件树也存在未知后缀图标缺失和尺寸不统一的问题。本次变更只修复这些已复现问题，不扩大 Agent 的权限或工具范围。

## 2. 协议与计划兼容

- 模型响应外壳仍严格校验；工具 arguments 的 JSON/对象校验交给 AgentLoop，失败结果带原 `tool_call_id` 返回模型，允许下一轮修正。
- 兼容无错误的 usage-only、`choices: null` 元数据和无 choices 心跳分片；损坏 JSON、空有效回复、重复调用 ID 与错误结构继续失败。
- `propose_plan.steps` 对模型暴露为字符串数组，降低兼容模型生成残缺嵌套 JSON 的概率；解析器继续接受旧 `{id,title}` 对象，避免破坏历史代码和测试。
- 计划确认卡显示时隐藏重复的计划状态卡，确认完成后恢复清单，写入和命令工具仍要等用户批准。

## 3. 步骤与循环终止

- 新配置默认最大步骤由 12 提高到 20，范围仍可在 1—50 内调整。
- 连续三次相同失败工具调用仍会提前停止，不能靠提高上限无意义消耗 Token。
- 每轮工具调用结束后立即复核完成门禁；若 `finish_task` 已使计划完成，则使用本轮可见摘要正常结束，不再额外索取一轮模型文本。

## 4. 文件树视觉

- 为未知后缀使用自绘通用文件 SVG，避免依赖字符或外部图标字体。
- 扩展常见源码、Web、配置、数据、文档、脚本和数据库后缀映射；同类文件使用稳定颜色而不是随机颜色。
- 统一目录树和变更列表中的图标占位、尺寸、文字行高、选中与悬停反馈，不改变目录展开状态和文件读取逻辑。

## 5. 验收证据

- 相关回归：OpenAI-compatible 客户端、AgentLoop、PlanController、ConfigStore 和文件图标测试均通过。
- 全量门禁：29 个测试文件、138 项测试通过，类型检查和构建通过。
- 真实模型：故障基线 2/6，经不完整修复 4/6，最终 6/6；测试文件哈希保持不变。
- 命令审批：拒绝时没有进程与退出码；再次批准后退出码 0，中央栏显示 6/6。
- 最新 Windows x64 免安装应用重新打包并启动，恢复历史、模型配置和项目均正常；本机最大步骤已保存为 20。
