# 用例文档

## 1. 参与者

- **开发者**：打开项目、查看代码、提交任务、审批命令和审查变更。
- **模型服务**：根据消息与工具定义返回文本或原生工具调用。
- **本地项目**：提供源代码、配置和测试环境。
- **RepoForge**：编排 Agent 循环、执行受限工具并呈现过程与结果。

## UC-01 打开项目并理解结构

**前置条件**：RepoForge 已启动。

1. 首次使用时开发者点击“打开项目”并选择本地目录；后续启动只尝试恢复上次成功授权的项目，路径失效则回到空白状态。
2. RepoForge 解析真实根路径，过滤依赖、构建、缓存与版本控制目录。
3. 左侧显示项目目录树；用户展开目录并点击文件，或按 `Ctrl+P` 以文件名/路径搜索并用键盘打开。
4. 中间显示文件语言、大小、行号和只读内容，并提供复制项目内路径、复制正文操作。

**验收重点**：不依赖外部编辑器；大于 1 MB 的文件不进入预览，也不能被 Agent 文件工具整体读取、替换或写入；项目外路径和逃逸符号链接被拒绝。

## UC-02 完成一个局部功能开发

**前置条件**：项目已打开；模型配置与 API Key 有效。

**输入边界**：任务说明必须是文本且不超过 20,000 字符；Renderer 的 `maxlength` 只提供即时反馈，主进程 IPC 会再次校验，不能依赖页面约束保障边界。

**触发**：开发者输入“为配置模块增加环境变量覆盖，并补充测试”。

1. RepoForge 将任务和当前选中文件路径交给 AgentLoop。
2. 模型调用列表、搜索和读取工具定位实现与测试。
3. 模型使用精确替换或写入工具修改文件；ChangeTracker 保存首个原始版本。
4. 模型提出测试命令和原因，桌面审批框显示命令与工作目录。
5. 开发者批准；命令输出、退出状态和耗时返回模型并显示在界面。
6. 若测试失败，模型读取错误、继续修改并再次申请验证。
7. 完成后 RepoForge 展示摘要、变更文件和双栏 Diff。

**后置条件**：修改留在本地项目中，不自动提交或推送。

**异常流程**：

- A1：旧文本不存在或出现多次，工具拒绝含糊修改，模型重新读取。
- A2：开发者拒绝命令，拒绝结果返回模型，模型选择替代验证或结束。
- A3：达到最大步骤，系统用中文说明停止原因并保留时间线、上下文与已有改动；开发者可点击“继续此任务”生成可编辑的继续指令，再明确发送，不会自动提高上限或产生新请求。
- A4：开发者点击停止，模型请求或本地进程被取消。

## UC-03 解释某个文件

1. 开发者从目录树选择文件并输入解释请求。
2. RepoForge 把选中文件路径作为任务上下文。
3. 模型通过只读工具获取必要代码及相关定义。
4. 系统展示解释与只读工具过程，不生成变更记录。

## UC-04 修复失败测试

1. 开发者描述失败测试或错误现象。
2. Agent 搜索测试与实现，申请运行最小相关命令。
3. Agent 根据真实 stderr/stdout 修改代码并重新验证。
4. 最终摘要区分“目标测试通过”和“完整测试套件未运行”。

## UC-05 审查并继续修改

1. 任务完成后，开发者在“本次变更”中选择文件。
2. 列表先显示新增/修改状态、文件类型、增删行和整体已审查进度；打开文件后将其标记为已审查。
3. 中间区域并排显示任务前快照和当前内容。
4. 开发者继续提交调整要求；新任务针对当前工作区执行。

## UC-06 命令审批

1. Agent 调用 `run_command` 并提供用途说明。
2. 右侧对话区出现内嵌审批卡，显示原因、完整命令和固定 cwd；工作台与时间线仍保持可见。
3. 开发者选择“运行命令”或“暂不执行”。
4. RepoForge 只执行已批准的调用；子进程继承普通运行环境，但剥离 Key、Token、Secret、Password、Credential、Auth 等敏感变量，再把真实结果返回 Agent。
5. 中央输出区为每次命令建立独立卡片，展示 stdout/stderr、退出码、执行耗时、审批等待和截断状态，支持全部/错误/测试筛选。
6. 同一任务多次运行测试时，系统从真实输出展示首次与最终通过进度；无法识别测试格式时只保留命令证据，不猜测数量。

## UC-07 配置模型

1. 开发者打开设置，填写兼容 API 地址、模型名、Key、最大步骤与超时。
2. 主进程验证配置；Key 使用 Electron `safeStorage` 加密后保存。
3. Renderer 只知道“是否已有 Key”和来源，不读取明文。
4. 若存在 `LOCALFORGE_API_KEY`，环境变量优先且不落盘。

## UC-08 为任务选择 Skill

1. 开发者打开任务输入区的 `Skill`，查看名称、摘要和来源文件；空列表可直接点击“新建 Skill”。
2. 新建时填写安全的 Markdown 文件名和正文；编辑时读取项目内真实文件正文，文件名保持不变。
3. 删除时先显示“确认删除”，第二次点击才移除项目文件；被删除项同时退出本次选择。
4. 开发者勾选本次任务需要的 Skill；未勾选项不进入上下文，一次最多选择 8 个。
5. 任务启动时主进程重新扫描文件，只注入仍存在且通过大小、类型限制的选中项。

**异常流程**：新文件名越界、重复、正文为空或超过 32 KB 时拒绝写入；符号链接或项目外目录不能作为存储目标。Skill 被外部删除、改名或变大时重新扫描后忽略；单次 Skill 正文总量限制为 64,000 字符；任务启动时不使用 Renderer 提交的任意文本替代文件内容。

## UC-09 维护项目 Memory

1. 开发者打开 `Memory`，记录包管理器、测试约定和界面语言等长期背景。
2. RepoForge 按项目真实路径保存内容，最多 12,000 字符。
3. 开发者勾选“在接下来的任务中启用”，后续任务才会带入 Memory，并要求模型以当前项目文件核实可能过期的事实。
4. 开发者可以取消启用而保留内容，也可编辑；点击“删除记忆”后再次确认，才会移除本机对应存储文件并自动取消启用。
5. 删除后弹窗保持可编辑的空状态，可以立即创建新 Memory；Memory 始终保存在应用数据目录，不写入项目和 Git。

## UC-10 回看任务历史

1. 开发者打开项目后点击 Agent 标题栏中的“历史”。
2. RepoForge 按项目列出最近 50 次任务，并显示完成、失败、停止、运行中或意外中断状态。
3. 开发者选择一项记录，查看任务说明、摘要、步骤、事件时间线、选中文件、Skill 数量和改动文件。
4. 若要继续处理，开发者点击“切换并继续”；右侧聊天区立即只显示该对话父链，输入区显示接续来源，下一条消息会携带对应的用户/Agent 文本上下文。
5. 开发者可以在发送前取消接续；运行中的历史不能被接续。
6. 应用异常关闭前仍处于运行中的记录，下次读取时显示为“意外中断”。
7. 开发者可点击“删除会话”并再次确认；系统从当前记录向上找到会话根节点，再删除该根节点及全部接续记录，但不删除项目文件或 Diff 所对应的真实改动。

**数据边界**：历史位于 Electron 应用数据目录，不写入项目；保存经过长度限制的消息和事件，不保存 API Key，不展示模型私有 reasoning 内容。任务运行时禁止删除会话，避免活动记录与磁盘状态竞争。

## UC-11 处理异常或空模型回复

1. 模型服务返回损坏 JSON、缺失 choices、错误的 tool call，或返回既无文本也无工具调用的空 assistant 消息。
2. ModelClient 先校验 HTTP 与协议结构；结构损坏立即抛出明确错误，不把残缺调用静默过滤。
3. 即使结构合法，AgentLoop 仍要求“最终文本”或“工具调用”至少存在一个；空回复记录为 `failed`，不能进入 `completed`。
4. 时间线和任务历史保存失败步骤与原因，当前项目中已经产生的真实改动仍可审查，但系统不会伪造测试通过或自动提交。

**区别**：工具参数或业务执行错误是可恢复结果，会以匹配的 `tool_call_id` 回传模型继续处理；模型协议损坏、认证失败或空回复属于不可恢复的本轮失败。

## UC-12 新建会话并添加文件附件

1. 开发者在同一会话继续输入“那就修复它”，RepoForge 自动将当前会话最后一次任务作为父记录，不要求再次打开历史。
2. 若要开始无关任务，开发者点击“新会话”；右侧聊天区和待发送附件清空，但旧任务仍保留在历史中。
3. 开发者点击“附件”，从当前项目选择一个或多个文本文件；输入区显示可逐个移除的文件标签。
4. 发送任务时，主进程重新读取并验证所选路径，将附件标为只读项目数据，再与当前 system prompt、可选 Skill/Memory 和会话历史共同组织模型上下文。

**边界与告知**：一次最多 8 个附件，仍受 1 MB 可读文件上限；单文件最多注入 24,000 字符，总附件正文最多 64,000 字符。附件必须位于当前项目，二进制内容被拒绝；按钮提示明确说明附件内容会发送给当前模型服务。

## UC-13 恢复未发送任务草稿

1. 开发者在任务框输入内容但未发送；Renderer 在短暂防抖后把正文保存到当前应用的本机存储槽，并同时记录项目路径用于校验。
2. 切换项目或关闭应用前再次同步保存；重新打开同一授权项目时恢复草稿，不把它加入历史或发送给模型。
3. 任务成功启动或开发者点击“新会话”后，当前项目草稿立即删除；模型配置缺失、请求未启动或本机存储不可用时不丢失输入、不阻断正常流程。

**隔离边界**：草稿按项目路径的稳定摘要分槽；读取时要求槽内项目路径完全一致，且只恢复任务文本，不恢复附件或隐式启用新的 Skill/Memory。

## UC-14 运行前检查与安全恢复

1. 开发者在设置中保存模型配置并点击“保存并测试”；系统用两个小请求分别验证文本/流式/usage 和原生工具调用，逐项显示结果。
2. 开发者写好任务后点击“发送清单”；系统只在本地构造与真实运行一致的 system、历史、Skill、Memory、附件和工具 schema，显示预计输入 Token，不发起模型请求。
3. 任务修改文件后，开发者可在 Diff 中二次确认撤销单个文件，或从变更区二次确认全部撤销。
4. 主进程比较当前内容摘要与 Diff 快照；若文件在任务结束后被编辑器或其他程序修改，则停止恢复并保留外部内容。
5. 开发者可从 Memory 弹窗导入/导出 Markdown，也可从历史详情导出任务证据报告；导出操作不包含 API Key 或模型隐藏 reasoning。

**安全边界**：自检不执行工作区工具；上下文预览不访问模型；恢复只处理当前 ChangeTracker 中的文件；导入受文本类型和长度限制。

## UC-15 管理和切换模型配置

1. 开发者在设置中查看已保存模型配置，新建配置时填写名称、API 地址、Model-Id、对应 Key、权限和响应档位。
2. 保存后新配置成为活动配置；旧单配置格式首次读取时自动迁移为默认配置，原加密 Key 保留。
3. 开发者可在顶栏选择其他配置，切换从下一条任务生效；聊天区显示切换提示，历史和报告记录实际配置名称及模型。
4. 自检结果保存到当前配置，顶栏区分“Agent 已验证、需检查、未测试、缺少 Key”。
5. 删除配置需要二次确认，并删除该配置自己的加密 Key；至少保留一个配置。Agent 运行期间不能保存、切换或删除配置。

**隔离边界**：保存的 Key 不返回 Renderer；一个配置不会继承另一个配置的 Key。`LOCALFORGE_API_KEY` 仍作为用户显式提供的当前活动配置环境覆盖。

## UC-16 手动编辑或新建项目文本文件

**前置条件**：项目已打开，Agent 当前未运行。

1. 开发者在 FILE 模式打开文本文件并点击“编辑”；界面保留打开时的正文、换行风格和内容摘要。
2. 开发者在轻量文本区修改内容，可点击“保存”或按 `Ctrl+S`；“取消”不会写盘，有未保存内容时需要再次确认放弃。
3. Renderer 只提交项目内相对路径、正文和打开时摘要；主进程重新校验任务空闲、路径、文本类型、1 MB 上限和当前磁盘摘要。
4. 摘要一致时原子边界内写入并刷新文件快照；若该文件原本位于本次 Agent 变更区，手动保存后解除 Agent 跟踪，避免把用户修改归因给模型。
5. 开发者也可点击“新建文件”，填写项目内相对路径与正文；父目录必须已经存在，目标不能已存在，创建成功后立即打开。

**替代/异常流程**：外部程序在编辑期间改变文件时，保存被拒绝并提示重新打开；路径越界、符号链接逃逸、NUL 二进制内容、正文超过 1 MB、父目录不存在或目标重名均不写盘；编辑未结束时切换文件、项目、刷新或启动 Agent 会被界面阻止。

**后置状态**：磁盘内容与中间 FILE 视图一致；手动变更不进入 Agent 历史或本次 Agent Diff，Git 状态仍由用户自行管理。

## UC-17 审批、调整并跟踪 Agent 计划

**前置条件**：项目已打开，模型配置有效，开发者在任务输入区选择“先规划”。

1. 开发者发送任务；Agent 此时只能列出、搜索和读取相关文件，不能调用修改或命令工具。
2. Agent 调用 `propose_plan` 提交 1—12 个可验证步骤和范围说明；界面显示内嵌计划确认卡。
3. 开发者可改写步骤、上移、下移、添加或删除，再选择“确认并执行”；也可退回计划。
4. 计划获批后才开放当前权限允许的写入和命令工具；Agent 用 `update_plan` 保持至多一个步骤为进行中，并在核验后标记完成或跳过。
5. 若目标、文件范围、架构或风险发生实质变化，Agent 重新提交修订计划并等待确认；拒绝修订时保留此前已批准计划。
6. 全部步骤进入完成或跳过状态后，Agent 调用 `finish_task` 记录真实核验和遗留事项。完成门禁通过后，最终文本才产生 `completed`。
7. 清单、版本、核验和遗留事项进入任务历史与 Markdown 证据报告；历史接续只复用用户/Agent 可见文本，不重放旧工具调用。

**异常流程**：模型未提交计划就声称完成、未收尾步骤就调用完成工具，或未调用完成工具就输出最终文本时，AgentLoop 发出完成检查失败事件并继续循环；计划被退回或用户停止时不会开放副作用工具。只读权限下即使计划获批，也仍不注册写入与命令工具。

**后置状态**：开发者能从界面和历史区分待确认、执行中、等待核验、完成与退回状态，并看到哪些事项实际验证、哪些仍未完成。

## UC-18 从代码选区发起任务

1. 开发者在 FILE 预览或轻量编辑区选中一段非空代码；界面在选区附近显示文件行号以及“解释、查错、修改、生成测试、加入任务”操作。
2. 开发者选择一种操作；RepoForge 计算项目内文件、起止行号和最多 8,000 字符的选区正文，并生成普通任务文本。
3. 新内容追加到右侧任务框而不是覆盖已有草稿；开发者可以继续补充、删除或改写，并自行选择直接执行或先规划。
4. 只有开发者再次点击“开始任务”后，选区文本才随普通任务请求进入现有模型流程。

**边界**：空白选区不显示操作；DIFF 模式不提供选区任务；选区过长时明确说明截断；生成草稿后仍受任务 20,000 字符上限和现有权限、审批、Skill/Memory 规则约束。

## UC-19 查看任务成果卡

1. Agent 任务完成后，右侧在最终回复下显示成果卡。
2. 卡片从本次持久化事件和 ChangeTracker 快照计算变更文件、增删行、工具/命令次数、工具失败、可识别测试数与 Token。
3. 开发者可直接查看变更、打开完整历史或准备继续追问；历史详情和导出的 Markdown 报告保留同一组结构化指标。

**证据规则**：测试数只从成功命令的真实输出识别；无法识别时显示命令次数而不猜测测试数。大文件行数统计使用有标记的近似值；旧历史没有结构化指标时从既有事件降级展示，不伪造缺失数据。

## UC-20 回放历史执行过程

1. 开发者打开任务历史并选择一条记录，点击“回放过程”。
2. 已保存的开始、模型、计划、工具与终止事件按原顺序依次点亮，界面显示当前项和总事件数。
3. 开发者可随时停止；停止或关闭弹窗后全部真实记录立即恢复可见，也可重新回放。

**无副作用保证**：回放只操作 Renderer 中已经读取的事件节点，不调用任何 Desktop API，不重新请求模型、不执行命令、不修改历史或项目文件，因此不产生 Token 或权限审批。

## 2. 演示用例

演示使用仓库内 `demo/order-pricing` 的零依赖 JavaScript 项目。初始实现预设边界与输入校验缺陷，6 项验收测试应当出现 2 项通过、4 项失败。Agent 只能修改实现，不能削弱或删除既有测试。视频展示“打开项目—选择 Skill—提交任务—批准测试—首次失败—精确修改—再次审批—6 项通过—回看历史—审查 Diff”的闭环。

2026-08-27 已使用真实 ModelScope 模型完成三轮：三轮都在工具安全拒绝不精确替换后自行重读恢复，并分别在第 10、10、9 步只修改 `src/shipping.mjs` 后达到 6/6。另一次尝试在修改前遇到远端 429 并如实失败。详细证据见 [14-真实模型验证.md](../质量与验证/14-真实模型验证.md)。

### 3.2 用例完成标准

一个用例只有同时满足以下条件才可标记完成：

- 前置条件、主流程、关键替代/异常流程和后置状态明确。
- Renderer 提交的数据在主进程或核心模块重新校验，不能只依赖界面限制。
- 正常结果和失败结果都能从时间线、历史、文件或真实退出码观察。
- 对应自动化测试或人工验收步骤已经执行，不以模型自述代替证据。
- 需求、设计、测试与追踪矩阵的编号保持一致。

### 3.3 用例变更流程

新增或改变用例时，先判断是否影响 P0 范围、安全边界、持久化格式或演示脚本；随后同步更新 PRD、设计、测试计划和追踪矩阵。08-31 候选版本冻结后不再增加用例，只修阻塞缺陷或纠正文档与实现不一致。总体生命周期和阶段门禁见 [16-中期生命周期基线.md](../历史归档/16-中期生命周期基线.md)。
