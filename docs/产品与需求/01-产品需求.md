# 产品需求文档

## 1. 背景与目标

RepoForge，中文名“代码锻造”，是一个独立的项目 coding agent 桌面应用。用户打开项目、查看代码结构并用自然语言给出任务；智能体通过模型原生 tool calling 自主读取代码、修改文件、执行命令和验证结果。

产品参考 Codex 的“项目 + 任务 + 可审查变更”交互方式，但不调用 Codex、Copilot 等现有 agent，也不借助 VS Code。目标是用清晰界面证明 Agent 核心逻辑、安全控制和本地工具均由本项目实现。

## 2. 目标用户

- 希望用自然语言完成局部代码修改的开发者。
- 需要在接受改动前理解执行过程与代码差异的开发者。
- 希望文件与命令操作留在明确选择的本地项目中的用户。

## 3. 产品边界

### 3.1 首个演示版本包含

- 独立桌面窗口，以及打开本地项目的入口。
- 项目目录树、代码预览、受限手动编辑/新建文本文件、本次变更列表和双栏 Diff。
- 自研模型调用循环和原生 tool calling 调度。
- 本地文件列表、搜索、读取、精确修改和命令执行工具。
- Agent 时间线、命令审批、错误显示、停止与步数限制。
- 任务级“直接执行/先规划”选择、可编辑计划审批、实时清单和完成核验。
- API 地址、模型、API Key、最大步骤和命令超时配置。
- 系统安全存储中的加密密钥，以及环境变量密钥入口。
- 项目内 Markdown Skill 的发现与按任务选择。
- 按项目隔离、用户可编辑且不进入仓库的轻量 Memory。
- 按项目隔离的任务历史，可回看状态、步骤、事件、摘要和改动文件。
- 可显式新建空白会话，或给当前任务添加有界的项目内文本附件。
- 上次授权项目、按项目未发送草稿、`Ctrl+P` 快速打开、带行号的预览和步骤耗尽继续入口。

### 3.2 暂不包含

- 完整代码编辑器、调试器、Git 客户端和终端模拟器。
- 多智能体、云端沙箱、远程执行和跨设备同步。
- 向量数据库、语义检索记忆、自动生成记忆和动态插件执行系统。
- 自动提交、自动推送或无人值守执行命令。

## 4. 功能需求

| 编号 | 需求 | 验收条件 | 优先级 |
| --- | --- | --- | --- |
| FR-01 | 用户能打开本地项目 | 选择目录后显示项目名、路径和过滤后的文件结构；只恢复曾经成功授权的上次项目，失效路径安全清除 | P0 |
| FR-02 | 用户能查看代码上下文 | 点击或通过 `Ctrl+P` 搜索打开文件后显示 UTF-8 内容、行号、语言和大小；可复制项目内路径或正文 | P0 |
| FR-03 | 用户能提交编程任务 | 非空且不超过 20,000 字符；发送后立即显示运行状态；同一时刻不启动第二个任务；未发送正文按项目恢复，成功发送或新建会话后清除 | P0 |
| FR-04 | 智能体能检索和读取文件 | 工具路径受项目根目录限制，输出具备上限与截断说明 | P0 |
| FR-05 | 智能体能修改文件 | 精确替换消除含糊匹配；首次修改前保存原始内容 | P0 |
| FR-06 | 智能体能执行本地命令 | 显示命令、原因和 cwd；用户批准后执行，支持超时与取消 | P0 |
| FR-07 | 系统能循环处理工具结果 | 工具结果按 tool call id 回传，模型可继续决策直至结束 | P0 |
| FR-08 | 系统具有明确停止条件 | 支持模型完成、用户停止、最大步骤、超时与不可恢复错误；最大步骤耗尽时使用中文说明并提供继续当前会话入口，不自动扩大上限 | P0 |
| FR-09 | 用户能观察连续会话与执行过程 | 用户问题、模型回复、工具参数摘要、结果、耗时和错误按顺序进入可滚动会话；重新打开项目恢复最近活动会话 | P0 |
| FR-10 | 用户能审查变更 | 本次变更集中列出，能查看修改前与当前内容 | P0 |
| FR-11 | 系统能展示验证证据 | 命令输出和退出结果可见，最终说明不夸大测试范围 | P0 |
| FR-12 | 用户能安全配置模型 | 支持兼容 API 与模型名；Key 不进入仓库、日志或模型上下文 | P0 |
| FR-13 | 用户能管理并选择项目 Skill | 可在界面新建、读取、编辑和二次确认删除 `.localforge/skills/*.md`；仅把本次勾选且仍存在的 Skill 注入任务；一次最多 8 个 | P1 |
| FR-14 | 用户能维护并选择项目 Memory | 按项目创建、更新和明确删除；保存与启用分开控制，只有选中时带入；内容不写入项目目录 | P1 |
| FR-15 | 用户能回看、继续、新建或删除会话 | 同一会话后续消息自动接续；按项目显示最近 50 次任务；可切换历史父链继续、新建空白会话，或二次确认删除整条会话接续链；不保存 API Key | P0 |
| FR-16 | 系统能拒绝损坏的模型响应 | 无效 JSON、空 choices、损坏或重复 tool call、非对象参数均产生明确协议错误，不误判为完成 | P0 |
| FR-17 | 用户能添加任务附件 | 从当前项目选择最多 8 个文本文件，可逐个移除；明确提示内容会发送给当前模型服务；路径、单文件和总上下文均有界 | P1 |
| FR-18 | 用户能选择权限、模型和响应档位并观察 Token | 只读模式不向模型暴露修改或命令工具；模型可从预设选择或填写 Model-Id；快速/标准/深入对应明确的单轮输出预算；接口 usage 优先精确显示，否则用 `≈` 标记本地估算 | P1 |
| FR-19 | 用户能在运行前验证模型 Agent 能力 | 分别报告连接、文本、流式、usage 和 tool calling；失败项有明确原因 | P1 |
| FR-20 | 用户能在发送前确认上下文 | 本地展示模型、权限、历史、文件、Skill、Memory、附件、工具数和预计输入 Token，预览不调用模型 | P1 |
| FR-21 | 用户能安全撤销本次文件变更 | 支持单文件和全部撤销；二次确认；当前内容与任务结束快照不一致时拒绝覆盖 | P1 |
| FR-22 | Memory 与任务证据可携带 | Memory 展示更新时间和注入预览并支持文本导入导出；历史可导出不含隐藏 reasoning 的 Markdown 报告 | P1 |
| FR-23 | 用户能保存并安全切换多个模型配置 | 顶栏快速切换；配置可新增、重命名和二次确认删除；Key 与自检结果按配置隔离；运行期间禁止切换 | P1 |
| FR-24 | 用户能手动编辑或新建项目文本文件 | FILE 模式可进入编辑并用按钮或 `Ctrl+S` 保存，也可取消；新文件只能创建在已存在的项目内目录且不能覆盖同名文件；保存前比较打开时内容摘要，冲突时拒绝覆盖；Agent 运行期间禁止操作；手动保存不计入本次 Agent Diff | P1 |
| FR-25 | 用户能控制并核验 Agent 执行计划 | 每个任务可选“直接执行”或“先规划”；规划模式在任何写入/命令前只开放读取与计划提交，用户可编辑、排序、增删并确认步骤；执行中同步清单，实质范围变化重新确认；所有步骤终态且提交真实核验证据后才允许完成 | P1 |

## 5. 非功能需求

| 编号 | 维度 | 要求 |
| --- | --- | --- |
| NFR-01 | 安全 | 文件路径经词法与真实路径双重校验；符号链接不能逃逸项目 |
| NFR-02 | 最小权限 | Renderer 无 Node 权限，只能调用 Preload 暴露的白名单接口；用户选择只读时，Agent 注册表不包含修改文件和命令工具 |
| NFR-03 | 可控 | 每个任务可停止；默认最大 12 个步骤；每条命令逐次审批；规划模式以动态工具注册表和完成门禁强制执行用户确认，不只依赖提示词 |
| NFR-04 | 可观察 | 工具名称、主要参数、耗时、命令输出、错误状态、计划版本、步骤状态和完成核验证据可见 |
| NFR-05 | 可靠 | 单个工具失败不破坏消息协议；损坏的模型响应明确终止，不能静默降级为完成 |
| NFR-06 | 性能 | 生成目录被过滤，过滤后的项目文件完整展示且扫描阶段不逐文件读取大小；任务最多 20,000 字符，Agent 单文件最多 1 MB；附件每个最多注入 24,000 字符且总计 64,000 字符；目录按展开状态渲染；时间线和输出有界 |
| NFR-07 | 可维护 | 模型、循环、工具、桌面服务和 Renderer 通过接口解耦 |
| NFR-08 | 可测试 | Agent、工具、路径和项目扫描无需真实模型或桌面点击即可测试 |
| NFR-09 | 兼容 | Windows 优先，开发环境为 Node.js 22.12+ |
| NFR-10 | 一致性 | 手动保存使用内容摘要进行乐观并发检查；外部变化不会被静默覆盖，手动修改与 Agent 变更证据明确分离 |

## 6. 成功标准

演示版本在真实小型项目中完成“理解代码—修改源文件和测试—运行测试—依据失败继续修复—展示可审查结果”的闭环。成功必须同时有文件变更和真实命令结果，不能只由模型文字声明。

## 7. 约束

- 不使用 LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen 或 CrewAI 等 agent 框架。
- 不调用托管代码执行、现有 coding agent 或编辑器 Agent 能力。
- 允许直接访问普通模型 API；首版直接实现 HTTP 与 tool calling 协议。
- 仓库公开并保留真实提交历史；2026 年 9 月 2 日截止后不再推送。
