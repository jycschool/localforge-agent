# 桌面连续操作流水线

## 1. 目标

本流水线针对“单个功能能用，但连续操作后显示或状态错位”的缺陷。它不把单元测试等同于视觉验收，而是把确定性合同、完整回归、Windows 打包和真实桌面复核串成同一条可重复路径。

## 2. 自动化阶段

本地执行 `pnpm run test:desktop`，GitHub Actions 在完整测试前单独运行同一命令，使桌面相关失败可以直接定位。当前专项门禁覆盖：

1. Renderer 元素 ID 唯一，`label` 与 ARIA 引用不悬空；原生弹窗必须有可访问标题，按钮必须显式声明类型。
2. 左右栏和上下区的四个分隔条保持存在，拖动高度计算不会吞掉相邻区域。
3. 文件图标、未知后缀、快速打开、轻量编辑和运行证据解析保持稳定。
4. 快速连续打开文件时，只允许最后一次请求更新预览；切换到欢迎页或 Diff 后，旧请求失效。
5. Java `out` 等生成目录不进入源码树；大型项目仍返回全部源码文件。
6. 命令请求被拒绝时，成果卡、历史和报告记录“未获批准”，不能计作已执行命令。

专项门禁通过后继续执行 `pnpm run verify`，覆盖类型检查、全部自动化测试和构建。交付候选另执行 `pnpm run verify:delivery`，不把真实 ModelScope Token 注入 CI。

## 3. 真实桌面检查矩阵

| 顺序 | 连续操作 | 观察点 | 退出条件 |
| --- | --- | --- | --- |
| 1 | 启动并恢复上次项目 | 标题、项目名、路径脱敏、文件数 | 无白屏，无生成目录噪声 |
| 2 | 展开目录并快速切换不同文件 | 展开状态、选中态、加载反馈、最终内容 | 最后点击的文件与预览一致 |
| 3 | 打开未知后缀文件 | 通用图标、标题、正文 | 图标不空白，文件可读 |
| 4 | 拖动四条分隔线并恢复 | 最小尺寸、滚动和操作区 | 任一区域都不会消失 |
| 5 | 打开 Skill、Memory、发送清单和设置 | 标题、按钮、长文本、禁用态 | 无截断到不可辨认，无控件重叠 |
| 6 | 新会话、选择历史并继续 | 消息顺序、父链、输入区 | 上下文与选中会话一致 |
| 7 | 先规划并修改计划 | 确认前副作用隔离、清单进度 | 未确认不写文件、不运行命令 |
| 8 | 分别拒绝和批准命令 | 命令卡、成果卡、测试进度、报告 | 拒绝不计执行；批准保留退出码 |
| 9 | 触发刷新、错误和完成提示 | 提示层位置、可关闭/消退、按钮可用 | 提示不遮挡任务提交区 |
| 10 | 缩窄窗口并复查主要流程 | 字号、换行、滚动、底部操作 | 核心操作仍可到达 |

真实桌面检查只读取或操作专用验收项目；涉及编辑、新建和命令的步骤使用副本，并记录是否产生文件变更。

## 4. 2026-08-30 执行记录

本轮从旧 Windows 包连续执行恢复项目、打开未知后缀、刷新、Memory 弹窗和新版重启，发现并关闭以下缺陷：

| 缺陷 | 根因 | 修复与回归 |
| --- | --- | --- |
| 提示浮层遮挡右下任务区 | Toast 固定在右下角 | 移至工作区右上方 |
| 四个上下文入口文字拥挤 | 420 px 面板内强制四等分 | 改为 2×2 网格，状态完整可辨认 |
| Java `out` 出现在项目树 | 项目扫描忽略集合缺项 | 忽略 `out` 并增加项目服务测试 |
| 快速切换可能显示旧文件 | 异步读取没有最新请求保护 | 增加请求版本保护、加载态和竞态测试 |
| 拒绝命令仍显示“已执行” | 在工具开始事件中提前累计命令 | 按工具结果的 `approved` 字段分别统计执行与拒绝 |
| 原生弹窗在系统树中没有名称 | 弹窗未关联可见标题 | 全部弹窗增加 `aria-labelledby`，合同测试强制检查 |

修复后专项流水线为 9 个测试文件、33 项检查通过；完整门禁为 31 个测试文件、146 项测试、类型检查和构建通过。重新生成 Windows x64 应用后，项目树不再显示 `out`，未知 `.iml` 文件可正常打开，右侧上下文入口在默认宽度下完整显示。

## 5. 边界

当前没有引入依赖像素截图的重型视觉回归框架。字体渲染、系统缩放、显卡差异和真实弹窗堆叠仍由 Windows 桌面矩阵检查；确定性状态、结构和计算尽量下沉到 Vitest 与 CI。若以后出现同一类布局缺陷反复回归，再评估有限截图基线，而不是立即维护整套脆弱快照。
