# 测试计划

## 1. 测试目标

验证 LocalForge 能安全、可控地完成本地 coding agent 闭环，并在模型错误、工具错误、路径逃逸、命令拒绝或用户取消时保持一致状态。

## 2. 测试层次

### 2.1 单元测试

- AgentLoop：文本完成、单/多工具调用、无效参数、最大步骤和取消。
- ToolRegistry：未知工具、执行异常和结构化错误。
- 路径安全：根目录、子路径、`..` 和相似前缀目录。
- 桌面项目服务：生成目录过滤、UTF-8 读取、语言识别和越界拒绝。
- ChangeTracker：首次快照、重复修改和排序。
- ModelClient：认证错误、限流、无效 JSON 和缺失消息。
- ModelClient 协议：分段文本、空 choices、损坏/重复 tool call 和非对象参数。
- ProjectContextStore：Skill 类型/大小限制、选中项过滤、Memory 更新、长度和项目隔离。
- ChangeRestore：修改恢复、新文件删除、外部内容摘要冲突和恢复后变更集合。
- ModelDiagnostics：文本、流式、usage、工具调用与部分能力失败报告。
- RunContextPreview / RunReport：发送清单边界、Token 估算、证据字段和 reasoning 排除。
- RunHistoryStore：项目隔离、运行中/意外中断映射、完成详情、敏感 reasoning 移除和非法 ID。
- TaskContext：选中文件/附件标记、单文件 24,000 字符和总计 64,000 字符边界。
- SystemPrompt：Memory 过期提示、Skill 内容和不可覆盖的安全边界。
- Preload：全部命令方法固定映射到白名单通道，三类事件可精确解除订阅。
- 主进程 IPC：请求/事件通道分离，文件、附件、Memory、历史、审批、任务和设置入参在进入核心逻辑前校验。
- ConfigStore：默认值、加密落盘、环境变量优先、服务切换 Key 隔离和输入校验。
- SafeMarkdown：标题、列表、代码块、引用、未闭合围栏、HTML 文本化和比较运算符保真。
- PathDisplay：Windows、macOS 和 Linux 用户主目录只在显示层折叠为 `~`。

### 2.2 临时工作区集成测试

- 列表、搜索、读取、精确替换和新建文件。
- 列表/搜索达到结果上限后提前结束，取消时停止目录遍历。
- 读取、精确替换和写入拒绝超过 1 MB 的单文件内容。
- 命令批准与拒绝，正确 cwd、真实 exit code、stdout/stderr。
- 命令继承普通环境变量，但不继承 Key、Token、Secret 等敏感环境变量。
- 命令超时、输出截断和取消。
- 脚本化假模型完成“读—改—测—失败—修复—再测”。
- 符号链接和最近既有父目录不能逃逸工作区。

### 2.3 桌面集成测试

- Electron 窗口能启动，CSP、Preload 与 IPC 正常加载。
- 任务说明类型、20,000 字符上限、当前文件和 Skill id 在主进程边界校验。
- 打开项目后目录树、项目名和文件数量正确。
- 文件点击进入代码预览并可显式进入轻量编辑，变更点击进入只读双栏 Diff。
- 设置仅返回 Key 的存在状态，不向 Renderer 返回明文。
- 审批决定只解析对应命令；停止能取消当前任务。
- 同一时间不能启动第二个任务或切换项目。

### 2.4 人工验收

在干净演示项目中执行：

1. 只读解释任务不产生文件变更。
2. 功能开发任务修改源文件和测试并通过验证。
3. 故意触发一次测试失败，Agent 根据真实错误修复。
4. 拒绝一次命令，确认没有进程启动且时间线记录拒绝。
5. 运行中点击停止，确认界面恢复且已有变更可审查。

## 3. 核心测试用例

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| T-01 | 模型直接返回说明 | 任务正常完成，不调用工具 |
| T-02 | 多轮工具调用 | 每个结果与 tool call id 匹配并进入下一轮 |
| T-03 | 达到最大步骤 | 中文说明安全结束并保留消息与步骤数；事件标记可恢复原因，界面提供继续入口但不自动发请求 |
| T-04 | 用户取消 | AbortSignal 结束任务并返回 cancelled |
| T-05 | 读取项目文件 | 返回 UTF-8 内容、相对路径和语言 |
| T-06 | 路径逃逸 | 项目服务与工作区工具都拒绝 |
| T-07 | 精确替换 | 仅一次匹配时写入并捕获原内容 |
| T-08 | 含糊替换 | 0 次或多次匹配均不写入 |
| T-09 | 命令批准 | 在固定 cwd 执行并返回真实退出结果 |
| T-10 | 命令拒绝 | 不创建进程，返回拒绝工具结果 |
| T-11 | 命令超时/取消 | 终止进程并标记真实状态 |
| T-12 | API Key 缺失 | 给出设置引导，日志与 Renderer 无明文 |
| T-13 | 变更 Diff | 左侧为首次修改前，右侧为当前内容 |
| T-14 | 失败测试后修复 | 第二次验证通过，摘要如实区分范围 |
| T-15 | 选择 Skill | 仅选中且运行时仍存在的 Markdown 内容进入上下文 |
| T-16 | 保存和选择 Memory | 同一项目可更新，不同项目互不读取，项目目录不产生文件；未启用时不读取、不注入 |
| T-17 | 连续会话/长输出 | 同一会话新任务不清空双方消息并自动继承上一轮；最近活动会话可恢复；用户向上阅读时不被流式更新拉到底部；节点和输出保持有界 |
| T-18 | 任务历史持久化 | 重启后可按项目读取；运行中遗留记录显示为意外中断；不保存 reasoning 和 Key |
| T-19 | 继续历史对话 | 选择历史后，新用户消息前按父链加入有界的用户/Agent 文本；不重放旧 system、tool call 和 tool result |
| T-20 | 新建空白会话 | 清除当前父链、待发送附件和聊天视图，不删除任务历史；首条任务不携带旧 `continueFromRunId` |
| T-21 | 添加项目附件 | IPC 拒绝非数组、非字符串和超过 8 个路径；正文按单文件和总量截断，第四个超限文件不进入上下文；历史只保存原始任务和附件路径，不复制正文 |
| T-22 | 损坏模型协议 | 无效 JSON、空 choices、坏调用、重复 ID 和非对象参数均明确失败 |
| T-23 | 命令计时 | 人工审批等待与本地进程执行分别记录，时间线不把等待误报为执行耗时 |
| T-24 | 空模型回复 | 既无文本也无 tool call 时记录失败，不能使用默认摘要伪报完成 |
| T-25 | SSE 流式模型响应 | 文本分片实时显示；reasoning 不展示；工具调用分片完整拼接后才执行；完整 JSON 仍兼容 |
| T-26 | 超过 2,000 个源码文件 | 过滤生成目录后完整返回全部相对路径，不按固定数量截断 |
| T-27 | 重复无效工具调用 | 连续 3 次相同工具、参数和错误时提前失败，显示具体工具与参数错误，不耗尽 12 步 |
| T-28 | 只读权限 | 注册表仅保留查看结构、搜索和读取工具，修改与命令工具不可调用 |
| T-29 | 工作区读写权限 | 保留全部工作区工具，命令仍走原有逐次审批 |
| T-30 | Token usage | 正确解析流末尾 usage-only 分片并累计输入/输出/合计 |
| T-31 | Token 估算与响应预算 | 服务不返回 usage 时标记 estimated；请求携带所选 4K/8K/16K `max_tokens` |
| T-32 | 全零 usage 占位包 | 非空回答收到 0/0/0 时不显示伪精确的 0 Token，改用带 `≈` 的本地估算 |
| T-33 | Skill 图形化 CRUD | 创建后能发现和读取，编辑更新摘要，删除后文件与选择均消失；越界名、重复名、空正文和静默改名被拒绝 |
| T-34 | Memory 明确删除 | 删除真实移除项目隔离记录，可重复删除且返回空状态；删除后取消启用并可立即重建 |
| T-35 | 删除完整会话 | 从任一接续记录删除时清除根与全部后继，其他会话仍可读取；活动任务期间 IPC 拒绝删除 |
| T-36 | 恢复上次项目 | 只读取主进程保存的成功授权路径；扫描失败后清除状态并返回空白，不接受 Renderer 路径参数 |
| T-37 | 未发送草稿 | 按项目独立保存、路径碰撞校验；任务启动和新建会话后清除，本机存储失败不阻断输入 |
| T-38 | `Ctrl+P` 快速打开 | 精确文件名优先于前缀、路径和子序列匹配；结果有界，键盘可选中并打开 |
| T-39 | 文件预览辅助操作 | 文件显示连续行号；路径与内容复制按钮只在文件/Diff 有上下文时可用 |
| T-40 | 模型 Agent 能力自检 | 连接、文本、流式、usage 和 tool calling 分项展示；工具调用失败不能被普通文本响应掩盖 |
| T-41 | 发送前上下文清单 | 与真实运行复用上下文组织和权限过滤；预览返回组成与估算 Token，但不请求模型 |
| T-42 | 单文件/全部恢复 | 当前摘要匹配时恢复首次快照或删除新文件；恢复后从变更集合移除 |
| T-43 | 外部修改冲突 | 任务结束后内容摘要改变时拒绝恢复，不覆盖编辑器或其他进程的新内容 |
| T-44 | Memory/证据导入导出 | Memory 导入受文本和长度限制，导出保留正文；任务报告包含可观察事件且不含 reasoning/Key |
| T-45 | 多模型配置管理 | 旧单配置无损迁移；不同配置的加密 Key 隔离；新增、激活、诊断记录和最终配置删除保护均可验证 |
| T-46 | 手动保存与冲突保护 | 内容摘要一致时保留换行风格并写盘；外部修改后拒绝保存且不覆盖磁盘内容 |
| T-47 | 手动新建文件边界 | 只在已存在的项目内父目录排他创建；重名、缺失父目录、越界和二进制正文均拒绝 |
| T-48 | 编辑状态与变更归因 | 换行归一化、脏状态和 UTF-8 字节数可独立测试；编辑时锁定上下文切换；手动保存后不继续显示为 Agent 变更 |

## 4. 当前自动化证据

截至 2026-08-28，`pnpm test` 共 24 个测试文件、118 项测试通过。新增证据覆盖手动保存摘要冲突、排他新建、父目录/越界/二进制拒绝、换行保留、脏状态、UTF-8 字节计算，以及新增 Preload/主进程固定 IPC 的入参和路由；既有 Agent 生命周期、模型协议、工具、历史、Skill/Memory、多模型配置、安全恢复和桌面边界测试继续通过。`pnpm run check`、`pnpm test` 与 `pnpm run build` 同时通过。

真实 ModelScope 模型已在 `demo/order-pricing` 完成三轮修改型任务：每轮均由基线 2/6 经工具错误恢复达到 6/6，LocalForge 外独立重跑仍为 6/6；步骤数分别为 10、10、9。另一次尝试在运行命令或写文件前遇到远端 429 并如实失败，随后已增加可取消的有限重试。真实只读任务在 6 步内正确预测 4 项失败测试，并保持 0 命令、0 改动。Preload 映射和主进程 IPC 边界已有自动化证据。最新开发候选构建已实际启动，打开演示项目后确认路径脱敏、目录树、源文件预览、历史数量和左右分栏拖动均正常；另从当时提交创建无构建产物、无 node_modules 的全新克隆，当时的 66 项测试、构建、交付检查和桌面启动均通过。视频彩排时长仍列为后续测试，不用功能成功掩盖免费服务可用性风险。

## 5. 发布门禁

- `pnpm run verify`（类型检查、118 项测试、构建）与 `pnpm run verify:delivery` 全部通过。
- 仓库扫描无 API Key、`.env`、大体积日志与构建产物。
- 所有 P0 需求通过自动化或有记录的人工验收。
- 演示任务在新克隆环境可复现三次。
- 视频中的完成状态与真实命令证据一致。

## 6. 测试执行过程

每个功能或缺陷按“测试点设计—相关测试—完整回归—桌面检查—证据记录”执行。相关测试用于快速反馈，完整 `pnpm run verify` 是候选版本门禁；涉及交付材料时还必须运行 `pnpm run verify:delivery`。失败测试不能被跳过或改弱来换取绿色结果。

| 阶段 | 输入 | 执行 | 输出/退出条件 |
| --- | --- | --- | --- |
| 测试设计 | FR/UC、架构影响、缺陷复现 | 写正常/异常/边界和安全场景 | 测试点可执行且可判定 |
| 开发验证 | 当前变更 | 相关单元/集成测试、类型检查 | 失败根因已修复 |
| 回归 | 候选工作区 | `pnpm run verify` | 118 项测试、类型和构建通过 |
| 系统检查 | 最新构建 | 启动、项目、会话、审批、Diff、CRUD | 固定烟雾矩阵通过 |
| 交付检查 | 候选提交与材料 | `verify:delivery`、视频/zip 人工复核 | 无凭据和禁入物，材料可打开 |

## 7. 测试环境与数据管理

- **单元/集成环境**：Node 22、pnpm 11.19.0、Vitest；临时目录在测试后清理。
- **桌面环境**：目标 Windows 机器、Electron 当前版本、最新 `dist` 构建。
- **演示数据**：`demo/order-pricing` 固定为 2 pass / 4 fail，Agent 只能修改实现，不能削弱测试。
- **模型环境**：最终 ModelScope Token 只存在安全存储；真实模型测试记录模型、步骤、命令、退出码和外部复核。
- **干净克隆**：不得复用工作区 `node_modules`、`dist`、Memory、历史或保存的 Key，以证明仓库自包含。

测试数据不包含真实凭据和个人文件。远端 429、认证和协议错误使用可控 mock 做确定性测试，真实服务只用于人工验收，避免把配额波动变成每次提交的随机门禁。

## 8. 流水线中的测试分工

当前本地流水线已经串联类型检查、118 项测试、构建和交付检查；GitHub Actions 尚未建立，状态不能写成“已完成”。计划的远端流水线使用 Windows、锁定的 Node/pnpm 和 `--frozen-lockfile`，执行 `verify` 与 `verify:delivery`，但不注入 ModelScope Token、不运行真实模型任务。

测试完善优先级为：先建立确定性远端门禁；再为新增状态逻辑补纯函数测试；最后固化桌面人工烟雾表。冻结前不为了追求形式覆盖率引入不稳定的重型 UI 自动化框架。总体流水线、缺口和系统验收矩阵见 [16-midterm-lifecycle-baseline.md](../archive/16-midterm-lifecycle-baseline.md)。
