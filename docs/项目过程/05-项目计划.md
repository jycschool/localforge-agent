## 3. 里程碑

## 4. 设计调整记录

项目最初将 VS Code 扩展作为低成本 UI 宿主。08-27 评审后调整为独立 Electron 桌面应用，原因是答辩中应清晰区分“项目自行实现”与“编辑器已有能力”。调整保留 AgentLoop、ModelClient、ToolRegistry、WorkspaceTools 和 ChangeTracker，只替换呈现层，未重写核心逻辑。详细取舍见 ADR-0001 和 ADR-0002。

## 5. 提交策略

使用小而真实的提交记录，不压缩或改写已推送历史。后续按“路线图—任务历史—协议解析—真实模型验证—命令稳定—演示交付”形成里程碑提交。提交必须对应已经完成且可验证的工作；不通过空提交、伪造日期或无意义拆分制造开发周期。详细优化顺序见 `10-剩余优化路线图.md`。

## 6. 每日检查点

- 更新实际完成项、计划偏差与剩余风险。
- 运行 `pnpm run check`、`pnpm test` 和 `pnpm run build`。
- 检查 Git 状态，排除 API Key、`.env`、日志、构建物和演示隐私数据。
- 实际启动桌面窗口并至少走一条人工验收路径。
- 推送当日已验证提交；9 月 2 日内部冻结后不再推送。

## 7. 完成定义

- 需求的正常路径和关键失败路径均已实现。
- 关键安全分支有自动化测试或明确的人工检查步骤。
- UI 能表达运行、审批、失败、取消和完成状态。
- 变更在真实本地项目中通过相关命令验证。
- 文档、代码、演示和答辩说法一致，不夸大验证范围。

## 8. 当前控制点（2026-08-28）

核心 Agent、独立桌面工作台、上下文管理、安全控制、多模型配置、可审批计划和真实 ModelScope 读改测闭环已经形成稳定里程碑。经明确批准，当前版本加入不扩张为完整 IDE 的轻量手动编辑，以及任务级“直接执行/先规划”、可编辑计划、执行清单和完成核验。当前质量口径为类型检查、构建和 127 项自动化测试通过；真实模型证据为三轮修改成功、一轮只读成功和一次如实保留的远端限流失败，计划模式仍需补一次真实模型桌面复验。

本计划不再复制逐功能完成清单。实际完成项和验证过程以 [09-开发日志.md](09-开发日志.md) 为准，需求状态以 [08-需求追踪矩阵.md](../质量与验证/08-需求追踪矩阵.md) 为准，当前尚未完成的工作只在 [10-剩余优化路线图.md](10-剩余优化路线图.md) 维护。剩余主要风险是确定性流水线、桌面回归、远端模型可用性、视频计时和最终材料，而不是核心 Agent 能否运行。

## 9. 中期阶段控制（2026-08-28）

中期后按“需求基线—设计基线—编码—系统验证—发布”的裁剪瀑布阶段推进。早期原型和桌面形态调整作为已经记录的可行性验证与计划偏差，不反向伪造为完全线性的开发历史。08-31 冻结新增 P1 功能，09-02 20:00 冻结远端推送。

阶段退出遵循以下门禁：

- 需求阶段：FR/NFR 和用例可测试，范围内外明确。
- 设计阶段：模块职责、信任边界、状态和数据流可映射到源码。
- 编码阶段：相关测试与完整 `verify` 通过，追踪文档同步。
- 验证阶段：自动化、桌面、真实模型、干净克隆和交付检查均有记录。
- 发布阶段：视频、README.txt、凭据、Git 状态和压缩包人工复核完成。

## 10. 估算与范围控制

中期使用 PERT 三点估算 `E = (O + 4M + P) / 6`，只估算当时尚未完成的工作，不反推没有可靠计时的历史工时。自动恢复、快速打开/行号和步骤耗尽恢复后来经明确批准进入范围并已完成；它们作为基线事实进入开发日志，不继续占用剩余待办。
