## 4. 范围控制

截止前不加入多人实时协作、多 Agent 编排、账号服务、云端执行、完整 IDE、调试器、Git 客户端、向量数据库或模型自主记忆。基础语法高亮也不为此引入重型编辑器依赖。新发现的问题按以下顺序处理：阻塞演示的缺陷 → 数据与权限风险 → 证据缺口 → 低风险体验问题。

## 5. 提交与推送原则

- 按真实完成的里程碑提交，不拆分无意义提交，不伪造日期。
- 不改写已经推送的历史；提交前运行相关测试和完整门禁。
- 提交使用已配置的 SSH 签名，并保留 `Signed-off-by` 声明。
- 完成项从本路线图移除，在开发日志中保留结果和证据链接。

## 6. 最终验收

- 评审者能从时间线、历史、Diff 和报告还原一次真实任务。
- 模型不能绕过注册工具、项目路径边界、权限模式和命令审批产生副作用。
- 错误、拒绝、取消和步骤耗尽都有确定状态，不显示虚假成功。
- 自动化、桌面检查和真实模型演示共同覆盖核心闭环，文档不夸大证据。
