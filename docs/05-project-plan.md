## 4. 提交历史计划

使用小而真实的提交记录开发过程，不压缩或改写已推送历史。建议提交序列：

1. `docs: establish requirements and delivery plan`
2. `chore: scaffold VS Code extension`
3. `feat: add model client and agent loop`
4. `feat: add guarded workspace tools`
5. `feat: add command approval and test feedback`
6. `feat: add change review and diff workflow`
7. `test: cover agent lifecycle and path safety`
8. `docs: finalize demo and submission guide`

## 5. 每日检查点

每天结束前执行：

- 更新实际完成项和剩余风险。
- 运行构建、单元测试和静态检查。
- 检查 `git status`，确认没有 API key、日志、临时文件或演示隐私数据。
- 推送当日已验证提交；9 月 2 日冻结后不再推送。

## 6. 完成定义

功能只有在以下条件全部满足时才算完成：

- 需求对应的正常和失败路径均已实现。
- 关键分支有自动化测试或明确人工检查步骤。
- UI 能表达运行中、失败、取消和完成状态。
- 变更在真实工作区中通过相关测试。
- 文档、实现和演示说法一致，没有夸大验证范围。
