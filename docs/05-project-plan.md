## 4. 设计调整记录

项目最初将 VS Code 扩展作为低成本 UI 宿主。08-27 评审后调整为独立 Electron 桌面应用，原因是答辩中应清晰区分“项目自行实现”与“编辑器已有能力”。调整保留 AgentLoop、ModelClient、ToolRegistry、WorkspaceTools 和 ChangeTracker，只替换呈现层，未重写核心逻辑。详细取舍见 ADR-0001 和 ADR-0002。

## 5. 提交策略

使用小而真实的提交记录，不压缩或改写已推送历史。后续按“路线图—任务历史—协议解析—真实模型验证—命令稳定—演示交付”形成里程碑提交。提交必须对应已经完成且可验证的工作；不通过空提交、伪造日期或无意义拆分制造开发周期。详细优化顺序见 `10-optimization-roadmap.md`。

## 6. 每日检查点

- 更新实际完成项、计划偏差与剩余风险。
- 运行 `pnpm run check`、`pnpm test` 和 `pnpm run build`。
- 检查 Git 状态，排除 API Key、`.env`、日志、构建物和演示隐私数据。
- 实际启动桌面窗口并至少走一条人工验收路径。
- 推送当日已验证提交；9 月 2 日内部冻结后不再推送。

## 7. 完成定义

- 需求的正常路径和关键失败路径均已实现。
- 关键安全分支有自动化测试或明确的人工检查步骤。
- UI 能表达运行、审批、失败、取消和完成状态。
- 变更在真实本地项目中通过相关命令验证。
- 文档、代码、演示和答辩说法一致，不夸大验证范围。
