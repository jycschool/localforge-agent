## 2. PDF 复核后发现的主要风险

### 2.1 “功能多”不是主要评分证据

原文允许功能很简单，面试重点是能否解释 Agent 为什么这样运转。因此截止前优先级应为真实多轮证据、失败路径和设计辩护，而不是增加完整编辑器、Git UI、多 Agent 或云服务。

### 2.2 视频必须证明真实编程过程

只展示漂亮界面或最终 Diff 不足。视频必须保留任务输入、工具读取、命令审批、失败测试、修改、再次测试和最终 Diff 的因果顺序。允许录制前先完整执行，再从同一条本地历史读取结果，以避免在两分钟内等待模型；但必须明确这是历史回放，不能把不同运行拼成虚假闭环。

### 2.3 提交历史本身是评审材料

评委会结合提交时间与内容了解开发过程。因此应按真实里程碑提交，减少无意义微提交，也不能人为改日期、压缩或改写已推送历史。推送频率可以按完整里程碑控制，但每个 commit 必须对应可解释成果。

### 2.4 凭据泄露是硬性违规风险

不仅仓库不能含 Key，README.txt 和视频也不能出现。发布前必须同时检查已跟踪文件、完整 Git 历史、构建产物、录屏画面和最终 zip；若曾误提交必须立即轮换，不能只删除当前文件。
