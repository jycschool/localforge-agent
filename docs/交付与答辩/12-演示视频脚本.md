# 两分钟演示视频方案

## 1. 视频目标与硬约束

视频必须在 2 分钟内展示 RepoForge 完成一个真实编程任务，并简要解释功能实现。建议成片控制在 1 分 45 秒至 1 分 55 秒，MP4 小于 200 MB，画面中不出现 API Key、系统用户名、无关目录或通知。

演示项目使用 `demo/order-pricing`。它没有第三方依赖，初始 6 项验收测试中 2 项通过、4 项失败，能稳定展示真实失败输出和二次验证。

## 2. 录制前准备

1. 将演示目录恢复到已提交基线，确认 `src/shipping.mjs` 仍使用错误的 `>` 边界且缺少校验。
2. 在演示目录手动运行一次 `pnpm test`，确认是 2 pass / 4 fail；录制前清空终端和无关通知。
3. 启动 RepoForge，只打开 `demo/order-pricing`，不要打开整个个人桌面或其他项目。
4. 在设置中提前配置模型；录制时不打开 Key 输入框。
5. 勾选 `Test-first demo verification` Skill；Memory 可写“界面和最终总结使用中文”并明确勾选启用，但不要在视频里临时输入隐私信息。
6. 将窗口设为 1920×1080 或 1600×900，系统缩放固定；关闭微信、邮箱等弹窗。RepoForge 会把界面中的用户主目录前缀折叠为 `~`，仍需检查其他画面元素。
7. 双击两条分栏拖动条恢复默认宽度，先打开 `src/shipping.mjs`，确认顶部路径、当前文件和测试数量与台词一致。
8. 预先确认选中 `calculateShippingFee` 后会出现代码选区工具条；录制时用“加入任务”生成草稿，再补充完整验收条件，避免手工重复输入文件路径和行号。

## 3. 演示任务原文

```text
修复 calculateShippingFee：普通会员订单满 99 元免邮，高级会员满 59 元免邮；subtotal 必须是非负有限数字，membership 只能是 standard 或 premium。不要修改或删除现有测试，先运行测试取得失败基线，再完成修复并运行同一测试验证。
```

### 4.1 台词速度预检

十段主台词约 340 个汉字，平均低于每秒 3 个汉字，留有英文术语和鼠标操作空间。开场和收尾已使用短句；先完整录制真实操作，再按同一条时间线配音，比边操作边讲更稳。若现场出现 429，应保留为失败素材或整轮作废后稍晚重录，不能把失败轮次与另一轮成功结果拼成一次连续任务。

## 5. 剪辑原则

- 可以将模型等待和测试执行片段加速 2× 至 4×，但保留第一次失败、审批动作、修改和第二次成功的时间顺序。
- 不剪掉退出码或失败输出，不把两次不同运行拼接成一次虚假连续任务。
- 关键文字至少停留 1.5 秒；鼠标移动保持缓慢，避免频繁缩放。
- 画面只录应用窗口；如必须录全屏，先隐藏任务栏中的个人信息和通知。
- 音频优先清楚，背景音乐可省略。最终导出 H.264 MP4，建议 1080p、30 fps、4-6 Mbps。

## 6. 录制验收清单

- [ ] 总时长小于 2:00，文件小于 200 MB，格式为 MP4。
- [ ] 展示真实任务、第一次失败、代码修改和第二次测试成功。
- [ ] 至少出现一次命令审批，并能看清 cwd 与命令。
- [ ] 出现代码选区任务、时间线、成果卡、Diff、任务历史和本地回放。
- [ ] 台词说明 AgentLoop、工具本地执行、消息回传和确定终止。
- [ ] 不出现 API Key、Token、环境变量值、用户名、无关聊天或邮件。
- [ ] 视频中的测试数量、退出码和最终摘要与真实执行一致。
- [ ] 使用 `pnpm run package:delivery -- -StudentName "姓名" -VideoPath "视频绝对路径.mp4"` 生成最终 zip，并确认其中只有 `README.txt` 与 `demo.mp4`。

## 7. 面试后的 30 秒设计介绍

“我把系统分成四层：Renderer 只展示；Preload 只暴露白名单 IPC；主进程负责项目、审批、密钥和历史；核心 AgentLoop 通过 ModelClient 与模型交互，并把 tool calls 交给 ToolRegistry。模型本身没有文件权限，所有读写都经过工作区边界检查，命令逐次审批。合法工具错误会回传模型继续修复，损坏的模型协议则明确失败。终止条件包括最终文本、用户取消、最大步骤和不可恢复错误。这样既满足题目要求的重要逻辑自研，也能从时间线、真实退出码和 Diff 证明任务确实完成。”
