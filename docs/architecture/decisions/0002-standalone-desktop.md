# ADR-0002：采用独立桌面 Agent 工作台

- 状态：已接受
- 日期：2026-08-27
- 取代：ADR-0001

## 背景

初版使用 VS Code 扩展承载界面，AgentLoop、模型协议和工具仍由项目自行实现。进一步评审后认为，文件树、编辑器和 Diff 来自 VS Code 可能造成能力归属的解释成本，也不利于从产品外观直接证明这是一个独立工具。

## 决策

改用 TypeScript 与 Electron 构建独立桌面应用。产品采用 Codex 风格工作台：左侧项目结构与变更，中间只读代码和 Diff，右侧任务时间线、审批与输入。Electron 仅承担窗口、系统对话框、安全桥接和加密存储；模型循环、工具调度、文件/命令执行与变更跟踪继续使用自研核心。

首版明确不是完整 IDE：不提供手动代码编辑器、调试器、Git 客户端或终端模拟器。

## 理由

- 产品可独立启动，不要求评审机器预装或启动 VS Code。
- 从源码和界面都能清楚区分展示层与自研 Agent 能力。
- 已有核心模块不依赖 VS Code，切换宿主无需重写 AgentLoop。
- 项目树、只读预览和 Diff 足以支撑演示，不需要实现完整编辑器。
- Electron 的 TypeScript 生态与现有代码一致，能在截止前控制迁移风险。

## 后果

正面影响：产品形态独立，答辩口径更清晰；可自行控制沙箱、审批、项目过滤和密钥边界。

负面影响：项目需要维护 Electron 主/渲染进程、IPC、静态资源和打包；代码预览功能弱于成熟编辑器。

风险控制：限制 UI 范围，只实现 Agent 闭环必需区域；使用 `contextIsolation`、sandbox、Preload 白名单、CSP 和 `safeStorage`；核心逻辑继续通过无桌面依赖的单元测试验证。

## 未选择方案

- 继续 VS Code 扩展：实现成本低，但能力归属存在解释成本。
- CLI：实现最少，但无法清晰呈现项目结构、审批、时间线和 Diff。
- 完整 Electron/Tauri IDE：自由度高，但编辑、调试和 Git 能力超出考核核心和截止时间。
- 封装现有 coding agent：不满足核心逻辑自行实现的约束。
