# ADR-0001：采用 VS Code 扩展作为产品形态

- 状态：已被 ADR-0002 取代
- 日期：2026-08-27

## 背景

项目需要呈现接近 Codex 或 VS Code Copilot 的编辑器内体验，同时必须自行实现 coding agent 的核心逻辑。可选形态包括命令行程序、独立桌面 IDE 和 VS Code 扩展。

## 决策

采用 TypeScript 编写 VS Code 扩展，在侧边栏提供任务输入、运行时间线、审批和变更入口；复用 VS Code 的编辑器、文件树、Diff 和终端基础能力。模型请求、消息循环、工具调度、文件与命令执行、上下文和停止条件由项目自行实现。

## 理由

- 比 CLI 更能呈现上下文、变更审查和运行状态。
- 比独立桌面 IDE 更少重复实现编辑器基础设施，能在有限工期内保证完整 agent 闭环。
- VS Code 扩展 API 只作为宿主界面和工作区接口，不提供现成 agent，因此不削弱核心实现的独立性。
- TypeScript 与 VS Code API 匹配，并方便共享工具协议和 Webview 消息类型。

## 后果

正面影响：首版可快速达到可用且可演示的编辑器体验，Diff 和工作区上下文更自然。

负面影响：首版依赖 VS Code，无法作为独立桌面应用运行；Webview 与扩展进程之间需要额外消息协议和安全处理。

## 后续修订

初始实现验证了 AgentLoop、工具协议和本地安全边界，但评审时可能难以直观看出哪些能力来自项目、哪些来自编辑器宿主。项目因此改为独立桌面应用；新决策见 [ADR-0002](0002-独立桌面应用.md)。本记录保留，用于说明设计演进，不改写已经发生的历史。

## 未选择方案

- CLI：实现快，但上下文、审批、Diff 和状态表达不足，不符合目标体验。
- 独立 Electron/Tauri IDE：自由度高，但需要自行处理编辑器、文件树、终端和打包，工期风险过高。
- 调用现有 coding agent：不满足核心逻辑自行实现的约束。
