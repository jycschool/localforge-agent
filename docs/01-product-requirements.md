# 产品需求文档

## 1. 背景与目标

LocalForge 是一个运行在 Visual Studio Code 中的本地 coding agent。用户通过侧边栏给出真实编程任务，智能体基于模型原生 tool calling，自主读取代码、修改文件、执行命令和验证结果。

项目目标不是复刻完整 IDE，也不是封装 Codex、Copilot 等现有产品，而是实现一个具备完整闭环、过程透明且能说明设计理由的编程智能体。

## 2. 目标用户

- 希望用自然语言完成局部代码修改的开发者。
- 需要在接受改动前理解执行过程和代码差异的开发者。
- 希望所有文件和命令操作留在本地工作区的用户。

## 3. 范围

### 3.1 首个演示版本包含

- VS Code 侧边栏对话界面。
- 当前工作区、活动文件、选区和显式引用文件的上下文。
- 自研模型调用循环和原生 tool calling 调度。
- 本地文件检索、读取、精确修改和命令执行工具。
- 命令审批、运行状态、错误信息、停止和步数限制。
- 代码变更摘要、文件清单、Diff 入口及测试结果。
- API 地址、模型、最大步骤和超时的基础配置。

### 3.2 暂不包含

- 多智能体协作、云端沙箱和远程执行。
- 自建代码编辑器、调试器或版本控制系统。
- 语义向量数据库、长期记忆和跨设备同步。
- 自动提交、自动推送或无人值守执行高风险命令。

## 4. 功能需求

| 编号 | 需求 | 验收条件 | 优先级 |
| --- | --- | --- | --- |
| FR-01 | 用户可在侧边栏提交编程任务 | 发送后立即看到任务状态，重复提交不会启动并发循环 | P0 |
| FR-02 | 智能体能获取工作区上下文 | 系统提示中包含根目录；可附加活动文件与选区 | P0 |
| FR-03 | 智能体能检索和读取文件 | 路径被限制在工作区内，结果包含必要的截断说明 | P0 |
| FR-04 | 智能体能修改文件 | 修改前校验目标与原内容，修改后记录变更文件 | P0 |
| FR-05 | 智能体能执行本地命令 | 命令在工作区根目录运行，具备审批、超时和输出上限 | P0 |
| FR-06 | 系统能循环处理工具结果 | 工具结果被追加到对话，模型可继续决策直至完成 | P0 |
| FR-07 | 系统具有明确停止条件 | 支持模型完成、用户停止、最大步骤、超时和不可恢复错误 | P0 |
| FR-08 | 用户能观察执行过程 | 每个模型回合和工具调用都有状态、摘要和结果 | P0 |
| FR-09 | 用户能审查代码变更 | 完成后能看到变更文件并从 VS Code 打开 Diff | P0 |
| FR-10 | 系统能验证实现 | 智能体可运行测试；最终摘要明确说明验证是否通过 | P0 |
| FR-11 | 用户能安全保存 API key | key 不写入仓库、普通设置、日志或模型上下文 | P0 |
| FR-12 | 用户能配置模型服务 | 可设置 OpenAI-compatible API 地址与模型名称 | P1 |

## 5. 非功能需求

| 编号 | 维度 | 要求 |
| --- | --- | --- |
| NFR-01 | 安全 | 所有解析后的文件路径必须位于已打开工作区；默认不执行工作区外操作 |
| NFR-02 | 可控 | 任意运行都能被用户停止；默认最大 20 个 agent 步骤 |
| NFR-03 | 可观察 | 工具名称、主要参数、耗时、退出状态和截断情况可见 |
| NFR-04 | 可靠 | 单次工具失败不会破坏消息协议；错误会反馈给模型或明确终止 |
| NFR-05 | 性能 | 除模型等待外，侧边栏交互应在 200 ms 内反馈状态 |
| NFR-06 | 可维护 | 模型、agent 循环、工具和 UI 通过明确接口解耦 |
| NFR-07 | 可测试 | 核心循环和路径安全逻辑不依赖真实 VS Code UI 即可测试 |
| NFR-08 | 兼容 | 目标环境为 VS Code 1.95 或更高版本、Windows 优先 |

## 6. 成功标准

演示版本必须在一个真实小型项目中完成“理解代码 - 修改多个文件 - 执行测试 - 根据失败继续修复 - 输出可审查结果”的完整流程。成功不能只由模型文字声明，至少要有文件变更和命令退出结果作为证据。

## 7. 约束

- 不使用 LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen、CrewAI 等 agent 框架。
- 不调用 Code Interpreter、Files API 或其他托管代码执行服务。
- 允许使用模型厂商的普通 API 客户端或直接 HTTP 请求；首版采用直接 HTTP 请求以展示核心协议实现。
- 仓库公开，保留真实提交历史，截止时间后不再推送提交。
