# 风险、质量与合规计划

## 1. 风险登记

| 编号 | 风险 | 概率/影响 | 应对措施 | 触发后的降级方案 |
| --- | --- | --- | --- | --- |
| R-01 | UI 工作占用过多时间 | 中/高 | 使用 VS Code 原生编辑器、文件树、Diff 与终端 | 保留单侧边栏，删除非核心动画和历史管理 |

## 2. 质量属性落实

- **正确性**：文件变更和命令结果来自真实本地工具；完成摘要引用实际验证证据。
- **安全性**：最小权限、路径边界、审批、超时、取消和密钥隔离。
- **可恢复性**：单个工具失败可反馈模型；任务失败不会自动提交或丢弃改动。
- **可解释性**：每一步展示工具、目标、结果和持续时间；失败与未验证状态不隐藏。
- **可维护性**：接口隔离模型、agent、工具、UI；核心模块可使用假实现测试。

## 3. 代码质量门禁

- TypeScript strict 模式，无未处理的类型错误。
- 核心安全逻辑必须有单元测试。
- 禁止把模型生成的字符串直接拼入 Webview HTML。
- 外部进程必须有超时和退出处理。
- 新增功能必须同步更新需求追踪与测试计划。

## 4. 提交与材料合规

- 公开 Git 仓库在题目发布后创建，保留完整、真实提交历史。
- 不压缩、改写或伪造已经推送的开发历史。
- 截止后不向仓库推送新提交。
- 提交用 `README.txt` 控制在 1000 汉字内，包含仓库地址、运行方法和特色功能。
- 视频为 MP4、2 分钟以内、200 MB 以内，不出现 API key 或其他凭据。
- 最终 zip 仅包含 `README.txt` 和视频，以本人姓名命名。

## 5. 评审清单

每个里程碑评审以下问题：

1. 本轮实现对应哪些需求和用例？
2. 哪些结论有真实测试或运行证据？
3. 哪些路径仍然依赖人工操作或尚未验证？
4. 是否引入新的权限、数据或截止风险？
5. 面试时能否解释这项设计为何存在，以及替代方案为何未选？
